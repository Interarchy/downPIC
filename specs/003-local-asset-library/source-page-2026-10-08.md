# AB-001 图片来源网页（本地实现）

日期：2026-10-08。状态：本地实现及隔离浏览器验证完成，待用户体验验收；未部署、未上架。

## 目标与确认范围

设计师从网页采集参考图后，能在图库右侧详情回到采集页面，继续阅读项目说明及关联资料。用户本轮明确只需本地跑通，不部署 CloudBase、不更新 Chrome Web Store。

核心路径：网页图片浮框保存 → 本地下载索引保存来源 → 打开图库图片详情 → 点击来源网页，在新标签页回访。仅保留可点击来源网页链接，不提供复制按钮。

范围外：反向搜图、自动追溯版权原始出处、云同步、图片文件内写网址、旁车文件及历史来源推断。保存的是采集当时的页面，不能保证是图片最初发布的网站；失效或需要登录的网页仍受原网站限制。

## 决策与实现

- 沿用 content.js 已发送的 pageUrl；后台将其作为 sourcePageUrl 写入 captureCatalogV4 的对应下载记录，保存在 chrome.storage.local。
- 只在主动保存图片时记录，不收集其他浏览历史。网址与图片直链分开，不用 CDN 图片地址或下载 referrer 猜测来源。
- 详情栏元信息最上方显示“来源网页”和完整可点击网址，保存时间在其下方；新标签使用 noopener noreferrer。长网址自动换行。
- 仅接受 HTTP/HTTPS 绝对地址，移除网址内用户名和密码；无效地址不生成可点击链接。使用 DOM textContent，避免把来源文字当 HTML 执行。
- 历史无来源记录显示“未记录来源网页”；本地导入显示“本地导入，无网页来源”。无需迁移或重建本地数据。
- 描述编辑、分类整理沿用既有索引更新方式，保留来源字段。来源不纳入向量文本、模型请求或统计，扩展内隐私说明已补充。

章程符合性：只修改既有下载索引、共享地址校验及详情渲染/样式，不新增依赖、权限、测试文件或框架。保持 direction/plugin，保留开始时已有的进度记录和需求池改动。不涉及云端资源、身份、密钥、日志、额度或预算，不修改后端配置。

## 本地体验

1. 在 Chrome 扩展管理页重新加载从本仓库 extension 目录加载的 ArchBuddy；仅商店安装的版本不会自动获得这些本地改动。
2. 刷新采集网页与图库页面，开启图片下载浮框，保存一张新图片。
3. 进入图库并点击该图，右侧“来源网页”应显示采集网址；点击打开原页面。
4. 关闭并重新打开图库检查保留情况；以前没有记录来源的图片不会自动补全。
