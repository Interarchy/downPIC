# V4 本地网页素材库实施计划

**分支**：direction/plugin | **日期**：2026-09-25 | **规格**：[spec.md](spec.md)

## 摘要

在现有 Chrome 扩展中新增全页素材库，直接读取 V3 已确认方案与来源图。增加少量本地整理元数据，实现网格、详情、检索、版本复制、继续使用、删除。先在本地加载扩展验证，随后由用户验收，再单独安排商店更新；本轮不改 CloudBase。

## 技术背景

- 语言：现有原生 JavaScript ES Module、HTML、CSS；不新增框架和依赖。
- 目标：Chrome Manifest V3 扩展，最低 Chrome 141。
- 存储：已确认方案及版本继续使用 chrome.storage.local；来源图继续使用现有 IndexedDB 仓库；当前生成图和评估工作稿维持会话存储。
- 质量门槛：相关脚本 node --check、Manifest 解析、页面元素与引用静态核对、git diff --check、既有白名单打包检查；不新增测试代码或框架。
- 范围：单次构建最多 3 张参考图；确认方案及历史版本全部本地保存，侧栏展示最近五份。页面不是独立服务。
- 隐私：浏览、搜索和整理不触发模型请求；仅点击生成描述才复用既有服务。新增 downloads.open 用于系统原图打开，不增加统计或密钥。

## 章程符合性检查

| 原则 | 设计结论 |
| --- | --- |
| 核心路径优先 | 先完成“侧栏打开 → 找到旧来源图 → 看关联 Prompt → 再使用”。 |
| 最小改动 | 复用 V3 方案集合、来源图仓库和删除路径；新增页面和必要元数据字段。 |
| 拒绝过度设计 | 不引入账号、同步、通用资产平台、下载目录扫描或新框架。 |
| 静态门槛 | 只执行适用静态检查与本地人工演示，不新增测试。 |
| 中文文档 | 规格、计划、任务、验收与交接均中文。 |
| 安全与隔离 | 本轮仅扩展本地存储；不改已登记的 CloudBase 服务、集合、身份、日志、预算。 |

设计后复核：上述门槛无例外。旧方案可通过字段缺省值显示，不做迁移批处理。

## 项目结构

- extension/library.html、library.css、library.mjs：素材库页面。
- extension/shared.mjs：在现有方案和来源图规范化逻辑中增加项目、分类和标签字段。
- extension/background.mjs：元数据更新和继续使用的最小消息路由，删除复用现有 scheme.delete。
- extension/sidepanel.html、sidepanel.mjs、sidepanel.css：独立素材库入口与回到方案的交接。
- extension/scripts/build-store-package.ps1：最终商店包白名单登记；本轮只做本地构建验证，不上传。
- docs/ARCHBUDDY_PROGRESS.md：状态、证据与未完成项。

## 顺序

1. 扩展本地模型并定义只对明确方案更新的消息契约。
2. 完成页面网格和详情，验证旧方案及缺图状态。
3. 加入项目、分类、标签和搜索筛选。
4. 加入版本复制、继续使用、删除。
5. 完成静态检查与本地演示指南；由用户在 Chrome 加载目录后验收。
6. 用户验收后另行进行商店包发布检查。本轮不部署、不上传。

## 风险与边界

- 取消五份截断后仍受本机容量约束，保存失败明确报错；旧版本已淘汰的记录无法恢复。
- 已保存来源图可能因浏览器清理缺失；详情仍保留文本，避免误称原图完整。
- 下载目录中的文件不属于插件本地存储，删除方案不触碰下载文件。

## 2026-09-25 方向修订

用户将侧栏第一栏改为“图词库”，把打开全页入口放入这一栏并要求打开后关闭侧栏。全页拆为“采集的图片”和“生成的提示词库”。图片以既有下载路径的项目类型、项目名称为两级目录；提示词板块保留既有 V4 方案功能。

实现沿用 downloads 权限和现有 IndexedDB 仓库：浏览器下载记录补齐旧图片条目；新下载写入轻量项目索引与限宽 WebP 预览，电脑下载原图不迁移。侧栏关闭 API 需 Chrome 141，Manifest 最低版本提升到 141。此轮仍为本地工作，不涉及 CloudBase。
## 2026-09-26 交互修订

Logo 弹窗收敛为三条入口与网页图片工具开关；项目类型管理移到侧栏“图资库”。类型的删除只从可选列表移除，历史下载记录仍由原目录解析；网页图片工具保留采集与保存。全页使用左侧导航，顶部两个紧凑图标切换图片和提示词；当时图片树的项目文件夹展示了缩略图；第三轮修订已将预览移到右侧文件夹内容。Prompt 卡片与详情把图片和对应正文放在一起。移除页底容量说明，隐私与数据边界由既有隐私页及项目文档承载。此轮仍仅本地验证。

## 2026-09-26 第三轮交互修订

左侧图片导航仅以文字列类型与项目文件夹；右侧先列项目文件夹，进入后展示该项目的图片卡。左侧项目列表独立纵向滚动。旧下载记录只提供路径，无法在未获本地文件授权时显示图像；由用户主动选择 ArchBuddy 下载目录后，以完整相对路径匹配缺预览记录，生成最长边 640px 的本地 WebP 预览，复用现有 IndexedDB 仓库和索引，不新增浏览器权限。

提示词“已确认方案”原为底层 Prompt 记录，1 个方案可关联多张参考图，故与右侧图片卡数量不一致。页面改用独立的用户分组元数据：分组 ID/名称与图片卡 ID→分组 ID 映射保存在 chrome.storage.local；初始卡片均在“未分组”，用户可多选卡片建立分组、移动、改名和删组。组的删除仅移走分组映射，既有确认方案及 Prompt 版本不变。Logo 弹窗三个入口统一绿色。本轮仍仅本地验证。

## 2026-09-27 实施补充

依照 revision-2026-09-27.md 推进：先修正文案与保存上限，再接分类名称映射与排序，再实现本地搜索、项目缩略预览和详情，最后连接单图描述生成与下载删除。共用现有 chrome.storage.local、IndexedDB、downloads 及图片分析服务，不新增服务接口或资源。静态检查与隔离浏览器只使用合成数据；真实模型验证使用一张合成学校示意图。系统图片浏览器的实际大图显示仍由用户本机验收。
