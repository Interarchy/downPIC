# 实施计划：ArchBuddy V2 结构化设计意图工作流

- **功能分支标识**：`001-design-intent`
- **仓库分支**：`direction/plugin`
- **规格文档**：[`spec.md`](./spec.md)
- **计划日期**：2026-09-20

## 摘要

V2 将现有“图片分析”和“提示词复制”两个独立能力连接为一条可编辑、可恢复、可重新分析的核心路径：用户选择一张建筑参考图，AI 返回 11 个结构化设计意图模块；用户可编辑、启用、停用或锁定模块；系统只把启用模块编译成最终提示词，并在每份新草稿首次复制完整提示词前进行一次全局确认。浏览器本地最多保留最近 5 份草稿；重新分析仅刷新未修改的 AI 建议。匿名行为统计必须由用户主动选择加入，且只记录白名单事件和结果类别，绝不记录图片、页面网址、提示词或自定义文本。

实现沿用现有 Manifest V3 扩展、原生 JavaScript 和 CloudBase Node.js 服务，不引入前端框架、状态库、测试框架或新的运行时依赖。扩展与后端在同一 V2 发布批次切换到版本化的 `modules` 契约，不保留多阶段兼容层。

## 技术上下文

- **语言/版本**：浏览器端 JavaScript ES Modules（Chrome 116+）；服务端 Node.js 24 ES Modules（沿用现有 `node:24-alpine` Dockerfile，不升级版本）
- **主要依赖**：Chrome Extension Manifest V3 API；现有 `@cloudbase/node-sdk`；现有 DeepSeek 视觉模型适配器
- **存储**：`chrome.storage.session` 保存当前图片选择和临时分析结果；`chrome.storage.local` 保存最多 5 份文本草稿及用户设置；CloudBase 文档数据库仅在用户选择加入统计后写入 `archbuddy_dev_events`
- **验证方式**：只执行静态语法检查、Manifest JSON 解析和现有打包检查；不新增、不运行自动化测试
- **目标平台**：Chrome 桌面浏览器扩展；腾讯云 CloudBase 容器服务
- **项目类型**：浏览器扩展 + 单体 HTTP 后端
- **性能目标**：本地编辑、模块开关和提示词重编译在一次交互内完成且不触发模型调用；分析过程 1 秒内显示进行中状态；正常网络下 60 秒内得到结果或明确错误
- **约束**：图片最大 10 MB；个人每天 20 次、ArchBuddy 每天 200 次；最近草稿固定 5 份；统计数据最多保留 30 天；不能持久化图片、来源网址、提示词和自定义文本到云端；不能影响下载/分类原有路径
- **规模/范围**：单用户、单浏览器配置（Profile）的 MVP；每份草稿固定 11 个模块；不做账号体系、跨设备同步、团队协作、向量检索、生成模型接入或自动 Agent 循环

## 设计方案

### 1. 分析结果协议

模型继续输出可部分恢复的标签文本，而非要求整段严格 JSON。每个模块使用固定标题，并包含“内容、依据类型、证据、置信度”四项；依据类型固定为“可见事实、合理推断、无法确认”。服务端解析后规范化为固定顺序的 11 个建议模块；缺失模块以空值、`uncertain` 依据和 `unknown` 置信度补齐。浏览器收到建议后再补充来源、审阅状态、启停和锁定等本地交互状态。

`/api/analyze` 切换为 `contractVersion: 2` 和 `modules` 单一契约。部署时先准备并静态检查扩展与服务包，再在同一发布窗口更新服务和扩展；契约不匹配时扩展给出明确的“版本暂不匹配”错误，不能把不完整结果静默当成成功。

### 2. 浏览器端设计意图状态

模块以 `reviewState=suggested|confirmed|modified` 表示审阅进度，并用 `enabled`、`locked`、`changed` 表示可叠加状态。界面按“停用 > 锁定 > 审阅状态”的优先级展示“建议、已确认、已修改、已锁定、已停用”，从而覆盖规格要求而不丢失恢复前状态。用户编辑后 `source` 变为 `user`，同时清空原 AI 证据并把依据/置信度改为不确定，避免旧证据错误解释新文本；这些审阅元数据均不进入最终提示词。

重新分析按模块键合并：

1. `reviewState=modified`、`locked=true` 或已停用模块保留原值和状态；
2. 未修改且未锁定的 AI 建议（包括此前已整体确认但未编辑的建议）替换为新建议；
3. 新旧建议不同则标记 `changed`；
4. 新建议回到“建议”状态；每份草稿的首次整体确认记录继续保留；
5. 合并完成后立即更新当前草稿。

### 3. 提示词编译与确认

编译器是本地纯函数：先输出不可编辑的整体生成准则，再按固定顺序输出所有 `enabled=true` 且内容非空的模块。来源、证据、置信度、编辑状态和分析元数据全部排除。

每份新草稿首次复制完整提示词前显示一次全局确认；确认后把当前启用且未修改的 AI 模块标为“已确认”，并记录草稿整体确认时间。后续编辑、启停或重新分析不要求重复全局确认，但新建议仍以“建议”状态显示。单个启用模块可以独立复制。任何复制都不触发模型调用。

### 4. 最近 5 份本地草稿

草稿保存在 `chrome.storage.local`，按 `updatedAt` 倒序保留 5 份，第 6 份写入时删除最旧草稿。草稿只保存结构化文本、模块状态、本地随机的参考选择标识和必要时间戳，不保存图片字节、缩略图或来源页面网址，以避免突破浏览器本地存储额度并降低隐私风险。首次成功分析且没有当前草稿时创建草稿；分析不同的当前参考选择时创建新草稿；只有明确的“重新分析当前草稿”操作执行合并；“新建草稿”只清空当前活动草稿 ID 和编辑上下文，不立即写入历史，下一次成功分析才持久化一份新草稿。该操作不删除历史草稿或已下载图片。恢复草稿后可继续编辑和复制；如需重新分析，用户必须重新选择参考图。

### 5. 可选择加入的匿名行为统计

统计开关默认关闭，与图片处理隐私同意分开保存。开关旁必须展示简明用途与 30 天保留期，并链接更新后的隐私政策。开启后，扩展只通过 `background.mjs` 发送契约白名单事件；`/api/events` 必须复用现有匿名会话 Bearer token 和一次 401 刷新逻辑，不能建立第二套身份。服务端只在 `ARCHBUDDY_ANALYTICS_ENABLED=true` 时接受事件，并复用 `start.mjs` 已初始化的一份 CloudBase store：同一次初始化同时向分析服务注入 `quota` 与 `eventWriter`，不得重复初始化 SDK。后端再次校验事件名和字段，使用服务端固定项目/阶段及匿名身份摘要写入 `archbuddy_dev_events`。统计失败不得阻断分析、编辑、复制或下载。

在创建或启用集合前，必须先更新隔离登记，确认集合权限为服务端管理，并对 `expiresAt` 配置并验证 30 天 TTL。TTL 未验证时，生产环境必须保持统计功能关闭。

## 实施阶段

### 阶段 A：结构化分析契约

1. 扩充固定模块定义和标签解析器。
2. 更新模型指令，要求输出内容、视觉证据和离散置信度。
3. 将 `/api/analyze` 与扩展一起切换到 V2 单一契约，不保留旧字段兼容层。
4. 对空模块、部分截断和格式错误给出确定性结果或明确错误。

### 阶段 B：设计意图工作台

1. 在侧边栏用可编辑模块卡片替代只读结果列表。
2. 增加可见事实/推断/无法确认、启用、停用、锁定和变化提示。
3. 增加本地提示词编译和全局确认门槛。
4. 粘贴或拖入多张图时拒绝并提示“一次只选择一张”，不得静默取第一张。
5. 在保存完成反馈中增加“继续分析此图”，复用同一图片选择和分析确认流程；保存本身仍不触发 AI。
6. 保持单图选择、下载和分类的原有独立路径不变。

### 阶段 C：草稿与重新分析

1. 增加新建、保存、恢复、删除消息和最多 5 份淘汰策略。
2. 首次分析或分析不同参考选择时创建新草稿；明确的重新分析才合并到当前草稿。
3. 让模块修改自动更新当前草稿。
4. 按既定合并规则接入重新分析。
5. 恢复草稿时明确提示：重新分析需重新选择参考图。

### 阶段 D：匿名统计与云端隔离

1. 先登记 `archbuddy_dev_events` 的归属、权限和保留策略。
2. 登记并增加默认关闭的环境变量 `ARCHBUDDY_ANALYTICS_ENABLED`，以及独立的统计选择加入设置。
3. 扩展现有单一 CloudBase store，一次初始化后同时注入 `quota` 与 `eventWriter`；增加 `/api/events` 和服务端字段白名单。
4. 配置并验证 30 天 TTL 后才允许生产环境启用。
5. 同步更新扩展隐私页、商店隐私政策、权限/数据使用说明、发布清单和公开 CloudBase 隐私站；重新部署隐私站并更新 Chrome Web Store 隐私披露后，才允许发布带统计开关的版本。
6. 记录不含敏感内容的部署与隔离证据。

### 阶段 E：静态验收与打包

1. 对所有变更的 `.mjs`/`.js` 执行 `node --check`。
2. 解析 `manifest.json` 并确认权限无新增。
3. 执行现有商店包构建检查，核对包内不含密钥、测试令牌、开发压缩包和本地草稿。
4. 可按 [`quickstart.md`](./quickstart.md) 进行非阻断的核心路径人工演示；它不属于强制完成门槛，自动化测试也不在本阶段范围内。

## 宪法复查（设计后）

| 检查项 | 结论 | 设计约束 |
|---|---|---|
| 是否出现非核心功能 | 通过 | 未加入生成图片、账号、云同步、知识库或跨行业框架。 |
| 是否引入不必要依赖 | 通过 | 使用已有原生 JS、Chrome API、CloudBase SDK。 |
| 是否要求新增测试 | 通过 | 仅静态检查和人工演示。 |
| 是否扩大浏览器权限 | 通过 | 计划不新增 Manifest 权限。 |
| 是否泄露或混用云端数据 | 通过 | 事件集合独立、服务端固定归属、内容字段禁止上传。 |
| 是否有未解决澄清项 | 通过 | 草稿数量、确认行为、重分析合并、复制内容和统计边界均已确定。 |

## 复杂度跟踪

无宪法例外。唯一新增云端资源是计划中的 `archbuddy_dev_events`，它直接服务于已确认的匿名行为统计需求，且在登记、权限和 TTL 验证完成前不得启用。
