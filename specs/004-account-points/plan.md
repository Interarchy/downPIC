# 手机号登录与积分账户实施计划

**日期**：2026-10-09 | **分支**：`codex/phone-login-credits` | **规格**：[spec.md](spec.md)

## 实施方式

在 V4.1 基础上复用原生 JavaScript、Chrome 扩展页面与 Node 本地后端。以独立本地模式接入账号鉴权和积分结算，保留已发布匿名链路。用持久化本地账本完成可重复演示的权益闭环，不引入云数据库或支付 SDK。

实现依赖顺序：

1. 明确账号、积分与调用次数的不同职责，登记本地资源和用户确认规则。
2. 增加本地验证码、持久化账号/会话、整数积分账本、每日保护、幂等预占与成功/失败结算。
3. 将已有反推、评估、核心视觉特点与向量接口接到账户鉴权和分项价格；原云端匿名模式不变。
4. 加入账号页、余额/流水、反馈申请、占位积分包和最小管理员操作；前端不自增余额。
5. 在侧栏与图库操作旁显示消耗；切换账号暂停自动处理，保留本地素材。
6. 生成独立本地扩展目录，完成适用静态检查和合成演示，记录限制与本机体验步骤。

## 本地运行与验收记录

后端与扩展已实现。运行及管理员命令见 [本地账号指南](../../cloudbase/LOCAL_ACCOUNTS.md)。在仓库根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File cloudbase/scripts/start-local-accounts.ps1
```

脚本生成 `extension/dist/local-account`，在 Chrome 加载该目录。数据保存在忽略目录 `cloudbase/dist/local-accounts`，登录凭据在扩展 origin 的 IndexedDB，公开账号状态经受信任的会话存储同步。账号与本地素材不上传云端。

本轮启动入口强制模拟 AI，不读取真实模型密钥。独立本地 500 次计数不与线上合并；接入真实模型前需另行确定统一预算，不能认为已获得额外真实额度。向量和语义搜索不生成虚假向量，模拟环境使用本地关键词检索。

已通过既有扩展 19 项及后端 20 项检查、相关 JS 语法和 PowerShell 解析。后端 8 组流程核验与 6 项边界核验通过，证据在 `cloudbase/dist/account-verification-1791477083780` 与 `cloudbase/dist/account-edge-verification-1791477387258`。独立浏览器 29 项通过、页面异常 0，实际目视 1440/1024 桌面与 360 侧栏截图，费用提示、跨页余额与账号隔离通过。报告 `extension/dist/account-points-20261009-review/verified-summary.json` 和 `cost-visibility-report.json`。最终 10 个 JS 模块语法、3 个 PowerShell 解析、Manifest 9 项资源与模块引用、26 文件凭据模式及差异检查通过，证据在同目录 `static-final-report.json`。

运行顺序为：生成本地扩展副本 → 启动本地账号服务 → 在 Chrome 加载 `extension/dist/local-account` → 手机号演示登录 → 执行反推/评估/描述 → 查看积分与反馈申请 → 管理员审核 → 重启核对持久化。

两个浏览器合成账号已归档到 `extension/dist/account-points-20261009-review/synthetic-accounts`，随后服务以零账号账本干净重启。复核补齐 V1 模拟标题兼容，通过既有合成函数验证。没有请求真实模型、短信或支付。
