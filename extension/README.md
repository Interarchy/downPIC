# ArchBuddy Beta Chrome Extension

建筑、室内与景观设计师的参考图助手。一键下载分类参考图，把视觉参考拆成可编辑意图模块，并通过生成后评估形成 Prompt 迭代闭环。当前本地开发版本：**V4.1（0.6.1）**。

V4.1 支持来源网页回访、图库左栏分类管理、浮框收起与 Logo 直达图库；修复新下载自动概要描述的时序问题，并简化侧栏导航。三张参考图构建、整体 Prompt 编辑与效果优化沿用既有能力。重新加载扩展后刷新相关页面即可使用。[版本记录](../docs/ARCHBUDDY_V4_1_RELEASE.md)包含范围、验证与已知限制。

更名后继续加载原来的 `extension/` 文件夹，无需重新安装。新下载图片使用 `ArchBuddy/` 目录，历史文件不移动；已保存的分类、开关和最近下载记录继续可用。品牌资源见 [品牌规范](../docs/BRAND.md)。

这是 `direction/plugin` 方向的本地 Beta 版本，完整产品由网页采集浮框、插件侧栏、本地图词库和现有 AI 服务组成。图词库与插件共享本地数据，支持分类、描述和自然语言搜索；独立桌面客户端与云同步不在本轮范围。V4.1 本轮仅更新 GitHub 源码，不代表商店已更新或后端重新部署。下文 V3/V2 章节保留历史交互说明，当前操作以 V4.1 版本记录为准。

## 固定本地测试目录

仓库中的 `extension/` 就是可直接加载的解压版扩展，也是后续开发唯一更新的本地测试目录。不要把 `dist` 中的 ZIP 当作日常开发版本反复解压；ZIP 只用于最终提交 Chrome Web Store。

首次加载后，后续代码更新只需要：

1. 在 `chrome://extensions/` 找到 ArchBuddy，点击卡片上的“重新加载”图标。
2. 刷新正在测试的网页。

不需要删除扩展，也不需要重新选择文件夹。Chrome 出于安全原因不会仅靠普通网页刷新自动重载扩展后台代码，因此“重新加载扩展 + 刷新网页”这两步仍然需要保留。

## 本地安装

1. 打开 `chrome://extensions/`。
2. 开启右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择本目录 `extension/`。
4. 打开一个包含建筑参考图的普通 HTTPS 网页，点击工具栏里的 ArchBuddy 图标。
5. 在弹窗中开启“网页图片工具”，再将鼠标移到网页图片上测试“保存”和“反推提示词”；也可点击“打开侧边栏”进入提示词生成或优化，点击“打开图词库”管理素材。

扩展不保存、接收或暴露 DeepSeek API Key。已发布 V1 继续使用 `/api/analyze`；V2 扩展只调用新增的 `/api/v2/analyze`，部署时必须先验证两条路由并存。CloudBase 自动缩容冷启动已预留等待时间；Key 仍只在服务端保存。用户首次分析时自动建立匿名安装会话，无需登录或配置 Key；匿名身份用于鉴权和执行个人每日 50 次、项目每日 500 次的额度规则（以已部署配置为准，详见[额度政策](../docs/ARCHBUDDY_QUOTA_POLICY.md)）。

## V3 三段核心链路（历史交互记录）

- **图片采集**：保存用户主动选择的网页图片，并按项目类型与网页标题整理下载目录；不触发 AI。
- **提示词构建**：最多三张参考图分别分析、就地编辑，各维度点击“加入／替换”后实时汇入底部加高预览。已采用内容继续编辑时同步更新。整体确认后才进入“最近确认的提示词库”并解锁复制。
- **效果优化**：先放生成图，再通过下拉框选择最近五份已确认提示词之一。明确发送后进行评估，每个维度给出符合程度、差异提醒及一份可直接编辑的原文；不再展示来源图、重复方案和独立修改草稿区。
- 点击“确认修改”保存新的文字版本后再复制；缺失来源图不拦截文字优化。复制只读取已确认文本。编辑元数据和评估内容使用会话存储；最多三张构建参考图在本地 IndexedDB 按方案 UUID 分区暂存。
- 当前与历史 PromptVersion 都只引用方案级来源图，不复制图片；最多保留 5 个版本，历史版本只读。
- 顶部只保留“图片采集、提示词构建、效果优化”三个阶段。完整网页素材库仍是后续独立 Spec，不在本版本中伪装实现。
- 当前 V3 不发送 `evaluation_*`、`suggestion_applied`、`prompt_version_created` 等新增行为统计事件，也未增加 CloudBase 集合、存储路径或其他云资源。

## V2 兼容链路

本节为历史交互说明；新版侧栏以 [2026-09-22 流程修订](../specs/002-effect-optimization/interaction-revision.md) 为准。

- 点击 Logo 打开功能弹窗；开关开启后，网页内容图片出现悬浮工具条，关闭后立即停止显示。
- 浮栏可直接切换预设项目类型，也可新增自定义类型；“保存”将图片写入 `下载/ArchBuddy/项目类型/网页标题/`。
- 下载成功后，浮栏会保持显示；浮栏和侧栏都可点击“在文件夹中显示”定位最近下载的图片。
- “反推提示词”优先读取网页原图；原图不可直接访问时，先隐藏 ArchBuddy 浮栏，再截取图片当前可见区域。
- 用户每次点击开始分析后还需再次确认，选择、粘贴、拖入、保存、打开侧栏或接受隐私说明均不会自动调用模型。
- 服务返回固定 11 个“本图候选意图”，不会自动全部进入 Prompt；用户只把需要的维度“加入当前方案”。
- 换一张图继续分析时，当前方案保持不变；不同维度继续累积，同一维度明确显示“替换当前项”，不会静默覆盖。
- 当前方案中的模块可逐项编辑、停用、锁定、确认和复制，编辑过程不调用模型。Prompt 由浏览器按固定顺序编译，“整体生成准则”始终位于最前；证据、置信度和界面状态不会进入 Prompt。
- 侧栏主流程采用减法布局：核心按钮控制在四字以内，候选正文默认三行；依据、置信度、证据、来源、整体准则和匿名统计收进底部默认折叠的“详细说明”。
- 最近 5 份方案文本保存在 Chrome 本地存储；V3 完整来源原图单独保存在扩展 IndexedDB，不保存来源网址，也不上传云端。失败不会用空结果覆盖方案。
- 保存成功后的“继续分析此图”只打开统一确认流程，不直接调用模型。
- 可选匿名改进统计默认关闭，可随时加入或撤回；CloudBase 集合、权限、TTL 和公开披露完成验证前，服务环境变量必须保持 `false`。

## 静态检查与打包

```powershell
node --check extension/shared.mjs
node --check extension/source-image-store.mjs
node --check extension/background.mjs
node --check extension/sidepanel.mjs
powershell -ExecutionPolicy Bypass -File extension/scripts/build-store-package.ps1
```

商店提交包输出到 `extension/dist/`。提交前还必须完成真实 Chrome 手测、真实 DeepSeek 调用、隐私政策公开部署和商店截图制作，详见 `store/RELEASE_CHECKLIST.md`。

当前限制：方案和来源图仅保存在当前浏览器，不支持账号同步；每次分析/评估只处理一张图片；完整网页素材库尚未实现；统计云端资源尚未创建或验证，保持关闭。SC-001、SC-002、SC-007、SC-008 属于后续真实用户与离线样本验证指标，当前不能宣称达成。

## 后端切换

公开后端地址位于 `runtime-config.mjs`。`BACKEND_MODE` 默认固定为 `cloud`；本地真实调用时可在开发工作区显式改成 `local`，只连接 `http://127.0.0.1:8080`。商店打包脚本会拒绝 `local` 模式。该文件只能包含公开地址，严禁放入任何 API Key、管理员 Token 或签名密钥。匿名会话签名密钥和模型 Key 只通过服务端环境变量注入。
