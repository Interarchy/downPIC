# ArchBuddy 01 排版候选独立核验

核验日期：2026-10-15（北京时间）。范围：本地比较页，未修改候选页面、正式站、CloudBase 或商店资源。

结论：三个候选均可供用户比较，推荐方案 2「三段式诊断」。综合排序为 2 → 3 → 1。无阻断性功能或布局问题。

## 视觉判断

- 方案 2：桌面三列的阶段名、小流程、诊断词、分隔线与大字结论共用基线；手机逐阶段阅读时，流程与对应痛点始终邻接。两处跨阶段箭头位于真实分界，大小一致。最符合「有秩序、对应明确、适合首页快速理解」。
- 方案 3：纵向五步与三组痛点的对应明确，桌面像清楚的过程诊断表。手机改为步骤并排、痛点紧随；本轮 balance 修正后的大标题断行整齐。桌面图高于方案 2，适合讲解型页面。
- 方案 1：桌面五步最紧凑，节点字高与基线最干净。但五列流程与三列痛点没有直接空间对齐，只靠 01—02 / 03—04 / 05 建立映射；手机先列完五步，再列三痛点，需要回忆编号。作为整体路径概览可用，作为「痛点对应图」弱于另外两种。

## 非阻断性建议

- P2 / 方案 1：若最终选择该方案，手机应把痛点放到对应步骤组之后，以减少往返查看；当前作为候选保留即可。
- P3 / 方案 2：阶段下的小诊断词与大字结论存在少量语义重复。若后续仍希望继续减字，可优先精简这一行；目前层级清楚，不影响读图。

## 核验依据

- 使用隔离 Chrome，在 1440×1000、1024×1000、390×844、360×844 四种视口检查三个方案，共 12 个案例。
- 实际打开并目视全部三个方案的 1440 和 390 截图；最终截图已等待样式切换完成，包含最新 panel ID、favicon 和方案 3 标题均衡换行修改。
- 12 例 documentWidth 均等于视口宽度，无横向溢出。节点文字无换行或裁切；同方案节点高度一致：方案 1 为桌面 32px / 手机 29px，方案 2 为桌面 58px / 手机 54px，方案 3 为桌面 30px / 手机 26px。
- 浏览器报告中 section-label 的 scrollHeight 高于 clientHeight 源于字体行盒，CSS overflow 为 visible，截图没有裁切。手机方案 3 两个 SVG 包围盒为 0 是隐藏跨组箭头，符合响应式设计；可见 SVG 均解析成功。
- 最终 12 例均为 200，页面异常与控制台错误为 0；此前初次载入的 favicon 404 已在修正后消失。

- 点击、左右方向键循环、Home、End、手动 hashchange 均正确切换对应方案与选中状态。
- 收集参考图 → 构思新方案 → 编写提示词 → AI 生图迭代 → 复用图与词的语义保留。方案 2 将第五步展开为「本次图与词 → 下次新方案」，表达复用；三个痛点均对应保存中断、表达与迭代困难、成果无法沉淀。
