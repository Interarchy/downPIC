# 01 流程图秩序重构 · 2026-10-15

## 目标与边界
只提供三版本地候选，保留旧配色轮次。用户选择前不改正式 showcase、不部署、不提交、不推送，不涉及云端资源。保留账号积分分支的全部既有改动。

## 设计依据
使用 OpenDesign 与 frontend-design 工作流；沿用 archbuddy-portfolio 设计系统的暖白、森林绿、低饱和砖红。参考 Whimsical 官方旅程图的阶段列/信息行分离、流程图的统一节点，以及 Dribbble 旅程模板的共同基线；实际图示由本项目原创。在线参考和视觉核查另记 references.md。

## 共通信息
完整路径：收集参考图 → 构思新方案 → 编写提示词 → 生图与迭代 → 复用图与词。三类痛点：逐张机械保存打断思路且参考难调用；提示词从零编写难表达意图、修改无依据；图片与提示词难沉淀、下次难复用。节点采用统一字数、字号与行高；不用断链小符号或分组括线。官方 Lucide chevron 为唯一方向图标；保留原 A 品牌标记。

## 三个不同结构
1. 对齐时间轴：上方五个等宽步骤，下面三个等宽结论，通过 01–02 / 03–04 / 05 的明确阶段标记对应。流程和诊断各占一条稳定的信息带。
   [01] → [02] → [03] → [04] → [05]
   [01–02 · 保存] [03–04 · 表达] [05 · 复用]
2. 三段式诊断：按参考输入、AI表达、成果复用分为三个连续阶段；每段小流程、主痛点、说明严格共线。完整流程按三段从左到右阅读，复用段表达本次成果到下一轮的关系。
   [参考：收集→构思] [表达：提示→效果] [复用：本次→下次]
   [打断创作思路]   [难以表达意图]   [难以再次复用]
3. 纵向对应图：左侧完整五步竖向时间线，右侧三个痛点按 2/2/1 步分组对应，去掉横向跨栏猜测。适合清晰讲解，图示会比横向方案高。
   [01→02] | 参考问题
   [03→04] | 表达问题
   [05]    | 复用问题

## 验收
三版真实可切换并支持 URL hash 与键盘；1440/1024/390/360 宽度不溢出；字体和连接方向清晰。独立代理查看截图验收，父代理不自审截图。正式 showcase 文件 SHA256 与制作前一致；预览仅 127.0.0.1。

## 2026-10-15 环形方案追加

用户提出五步围成环，第五步回到第一步；左侧圆环只断三处，右侧三类痛点逐一对应。本轮将比较页原方案二、三归档，再加入两版环形候选：单层开放环与双层理想/现实对照。三处缺口分别在 01→02、02→03、04→05；第三步到第四步属于“意图表达与效果迭代”同一问题段，右侧 B 的说明覆盖提示词从零编写与多轮修改缺少依据。环上 A/B/C 标记与右侧同字母结论对应，避免把步骤 01–05 与三种痛点编号混淆。两处完整连接为 03→04 与 05→01；后者是下一轮创作的复用回路。

环形图借鉴 Figma/FigJam 的 Causal Loop Diagram 官方页面所示环绕节点与反馈路径，仅参考关系表达。画面为本项目自绘的 CSS 圆环、品牌色与文字，不复制参考图像，也不引入新的图标包或依赖。保持上版横向方案在正式网站本地源码中，环形候选只在比较页；用户选定后再定稿，不部署公网。
