# ArchBuddy 插件交互简化方案与选择记录

日期：2026-10-08。用户已选择方案一的独立控制位置与方案二的收起方式组合，并进一步确认分类管理移入图库左栏。本目录保留原有三个静态候选 HTML 作为讨论记录，不再处于等待选择状态；最新决定按下节说明用于本地插件实现，不部署 CloudBase 或更新谷歌商店。网页使用本机已有建筑参考图，只作视觉演示，来源网址与描述为示例。

## 已确认的组合方案

1. 图片浮框右侧使用 Lucide 风格的线形 chevron 按钮，悬停或聚焦提示“收起”；点击后折叠为小 Logo 加“展开”；Logo 点击直达图库，“展开”文字恢复浮框。收起与网页图片工具总开关分开，已发出的保存或分析任务继续执行。
2. 侧栏保留“图词库”“提示词生成”“提示词优化”三个纯文字入口。“图词库”点击直接打开完整页面，不加右上箭头，不再保留重复的打开按钮。
3. 分类管理全部集中到图库左栏，取消侧栏里的“管理分类”入口。图库“图库 / 词库”下面、“全部图片”上面放置分类输入框，以“输入新增自定义分类”占位文字提示用途，各分类右侧提供“改名”和“删除”；有图片的分类需先将项目移走，仅空分类可删除，素材不随分类删除。分类排序与项目跨分类拖动保留。
4. 浏览器 Logo 菜单只保留“打开图词库”“打开侧边栏”两个功能入口，网页图片工具总开关独立保留。
5. 图片详情元信息按来源网页、保存时间排列，去掉分类和项目的重复信息；保留图片预览、概要描述和后续操作。图片浮框移除“分类”标签文字，并缩窄保存图片、反推提示词按钮。

上述决定覆盖静态候选中的旧导航箭头、侧栏分类入口和关闭总开关方案。原 HTML 不再追改为最终界面，实际实现与验证进度以仓库交接记录为准，不能把静态演示视作验收证据。

## 历史三个候选

- option-one.html：独立关闭按钮（初始推荐）。关闭图片浮框总开关；支持提示撤销，或在浏览器 Logo 菜单重新开启。Logo 保持品牌识别。
- option-two.html：Logo 收起/展开。只折叠当前图片工具条，保留小图标恢复，不等同于关闭总开关。最紧凑，但用户需要学习 Logo 的新用途。
- option-three.html：浮框内直接开关。关闭后保留轻量开关条，可在网页内重新开启；状态清楚，但比纯关闭占用更多画面。

每个页面都有“网页图片浮框 / 图库右侧详情 / Logo 功能菜单 / 侧边栏与分类”四个界面，页顶可切换三个方案。交互只在内存中演示，不调用扩展 API、模型服务或下载。

## 候选阶段的共同调整

1. 详情信息：来源网页第一、保存时间第二；去掉项目/分类重复信息，保留概要描述和后续操作。
2. 图片浮框：移除“分类”标签文字，保留可理解的类型下拉；保存图片及反推提示词缩窄至紧凑尺寸。
3. Logo 菜单：只保留“打开图词库”“打开侧边栏”两个功能入口，保留浮框总开关。
4. 图词库点击直接打开独立页面，移除侧栏里重复的大按钮。候选生成时分类管理仍保留在侧栏，三个方案展示不同位置的独立管理入口；该安排已被上方最新决定替代。
5. 分类页从上到下：导入本地文件夹、新建分类输入、项目类型列表。提示词生成和优化仍能进入。

## 候选阶段的实施建议（已由组合方案替代）

初始建议优先方案一：显式关闭，图词库使用 ↗ 表明外部页面，管理分类从侧栏右上进入；方案二可单独组合。用户最终选定右侧独立收起、Logo 加文字展开，并取消箭头和侧栏分类管理，以上初始建议不作为现行实施要求。

本地实现须同步侧栏导航与请求阶段状态、开关存储和跨标签事件；收起正在保存或分析的浮框不得取消已经发出的任务。本文件记录选择与边界，不宣称尚未完成的验证通过。
