# ArchBuddy 本地图词库可靠性风险核查

日期：2026-10-09。状态：风险评审与改进建议，尚未实施修复。

## 1. 目标、范围与证据边界

用户担心长期积累大量图片后，因误操作或系统异常导致图库失联、原图或整理成果丢失。本次按“文件、索引、整理信息、可恢复能力”核查当前实现，提出优先级及验收方向。

核查基线：本地 codex/phone-login-credits 分支，包含原有未提交的账号积分等修改，数字版本 0.6.1。direction/plugin 是当前 HEAD 的祖先。没有读取用户实际 Chrome 资料、执行清除或删除、进行破坏性验证，也未核对当前商店安装包。本报告的确定性代码发现针对当前工作区；真实用户影响规模和故障概率未测量。

已读取 AGENTS.md、项目进度、章程、产品形态与 CloudBase 隔离文档。使用 Context7 和 Chrome 官方文档核对平台规则；源码审阅覆盖 library、background、folder-import、source-image-store、library-vector-index、shared 与 manifest。没有新增测试文件或框架。

本轮仅更新本地文档，不涉及云端资源、用户数据、身份、密钥、日志、统计或预算，不修改插件功能、不提交推送、不部署、不更新商店。

## 2. 当前真实存储方式

图词库是 chrome-extension://<扩展ID>/library.html，属于扩展自带页面，不是独立互联网网站连接用户硬盘上的统一数据库。

| 资产 | 实际存放 | 恢复边界 |
| --- | --- | --- |
| 网页采集原图 | Chrome 下载目录的 ArchBuddy 子目录 | 卸载插件不自动删除下载文件，但移动、改名、删除会影响原路径定位 |
| 网页采集预览 | 扩展 IndexedDB；最长边 640px 的 WebP | 不是原图备份；原图丢失后不能恢复原分辨率 |
| 导入文件夹的图片 | 导入时复制完整 Blob 到扩展 IndexedDB，电脑源文件保留 | 导入成功后浏览不依赖源文件夹持续授权；当前仅支持 PNG/JPEG/WebP、单图不超过 10MB |
| 来源图、已确认效果图 | 扩展 IndexedDB | 存的是当时提交的图片字节；从采集预览进入流程时，不应理解为下载原图的独立完整备份 |
| 分类、描述、来源网址、方案、Prompt版本、分组和图片引用 | chrome.storage.local | 只保留原图文件夹无法恢复这些整理成果 |
| 语义搜索向量 | 单独的本地 IndexedDB | 可重新计算，不应与原图和人工整理信息同等处理 |
| 尚未确认的部分构建/优化任务 | chrome.storage.session | 浏览器重启、扩展重载等导致会话数据清除；区别于已确认入库资产 |

目前有文件夹图片导入和旧下载图预览补齐；没有完整资产包导出/导入恢复、自动备份、回收站或通用失联重连。账号用于 AI 身份和积分，不构成图库云备份或跨设备同步。

## 3. 已确认的关键实现问题

### R01：清空下载历史会连带删除整理成果（P0）

证据：background.mjs 的 chrome.downloads.onErased 调用 forgetCapturedDownload；该函数删除预览 Blob、captureCatalogV4 对应条目及 capturePreviewsV4 映射。library.mjs 的 loadCaptures 又依赖下载历史列出采集图片。

后果：用户只在 Chrome 中移除/清空下载记录，原文件可仍在磁盘，但图库图片消失，关联的描述、来源网址和虚拟分类信息也可能被当前代码主动删除。若扩展当时未接收到事件，不能断言所有元信息均被删，但失去下载记录依然使当前列表无法列出它。

修复方向：下载历史仅作为采集事件及原文件定位线索；使用独立资产ID和持久资产目录，onErased 只标记历史关联失效，不删除资产。图库删除必须是独立、明确的用户操作。不得为恢复而取消不同安装的归属校验。

### R02：采集列表受默认 1,000 条下载查询限制（P0）

证据：library.mjs:798 使用 chrome.downloads.search({})；官方 DownloadQuery.limit 默认 1000。本地代码在查询返回后才按当前扩展和状态过滤。

后果：浏览器全部下载记录超过 1000 条后，部分采集图片可能未进入结果；其他软件包、文档下载也占用查询结果数量，并非必须在 ArchBuddy 中积累 1000 张才触发。没有指定排序，不能断言固定遗漏最老或最新图片。数据未必删除，但页面计数、分类、搜索和空分类判断可能不完整。

修复方向：短期分页或明确查询范围并完整读取；长期列表读取独立资产目录。大量记录应分页显示，避免把取消查询上限误当成完成大图库性能支持。

### R03：浏览器本地数据没有独立恢复副本（P0，长期使用门槛建议）

证据：当前代码和素材库规格未实现完整备份恢复。原图下载、文件夹导入、关联预览均不等于备份整库。

后果：卸载、浏览器资料清除或硬盘损坏后，可能只剩下载原图，分类、描述、Prompt及版本关系无法完整还原。导入源文件如果另被删除，则库内副本可能成为唯一原件。

修复方向：先做用户可导出的版本化资产包和恢复预检，至少包含元数据、库内图片字节及引用关系；采集原图如未包含，必须逐项报告并引导用户选择目录打包。备份需保存到扩展之外，异盘副本用于抵御物理磁盘故障。优先默认合并恢复，避免覆盖现有库；不导出账号凭据。

### R04：容量保护不完整（P1，高影响）

证据：manifest 无 unlimitedStorage；源码未发现 navigator.storage.persist/estimate 或统一容量预警。chrome.storage.local 目前默认限额 10MB，存放元数据而非全部图片；图片 IndexedDB 还有独立的配额与物理磁盘约束。

已有保护：图片仓库事务错误区分容量不足，写入后回读检查归属、MIME 和字节数；导入元数据写入失败会尝试删除本批新 Blob，不主动淘汰既有资产。

缺口：下载流程吞掉归档队列错误后仍可能返回下载发起成功；不能据此承诺“下载文件、预览和整理信息全部保存成功”。缺少统一保存完成状态及容量预警。回读元数据检查不是文件内容校验和。

修复方向：分别显示磁盘下载、资产登记、预览保存状态；容量不足明确失败并保护旧数据。先测实际字节占用，再评估持久化申请或 unlimitedStorage；权限不替代备份，也不创造物理磁盘空间。

### R05：删除没有回收站，跨存储删除不是整体事务（P1，高影响）

证据：library.mjs 删除确认中“同时删除原图”默认不勾选；background.mjs 的 deleteCaptures 删除导入元数据后再删 Blob，deleteScheme 则先删 Blob 再写元数据。两种存储及文件删除不能在当前代码中作为一个事务提交。

后果：误确认后无法在插件内撤销；删除中断或第二步失败可能留下“文字在、图片缺失”或“图片在、索引缺失”。删除整个方案影响该方案来源图和版本，不只是移除一个可见卡片。原图物理删除按界面提示视为不可恢复，不承诺进入系统回收站。

修复方向：软删除、可恢复期、明确整项目/整方案影响清单；物理文件删除单独确认。破坏性操作先记录可恢复状态，完成后再清理。

### R06：导入和并发编辑有一致性窗口（P1，机制明确，现场未复现）

证据：folder-import.mjs 一次读取 existing 列表，逐张保存 Blob，最后整批写回 importedAssetsV4；Web Lock 只协调导入任务。后台的描述保存、项目移动、删除使用另一条进程内队列，不与该锁统一；方案和分组也存在整集合读后写回。

可推演路径：大量导入尚未结束时，在另一图库页修改旧图描述或删除旧图，随后导入用旧快照写回，可能覆盖刚才的修改或恢复已删条目；此时对应 Blob 可能已删除。导入中途关闭标签页，可留下已写入但尚无目录记录的 Blob。重新导入去重只看路径、大小和修改时间，不校验旧 Blob 是否仍在，因此不构成通用修复。

修复方向：同类资产写入统一串行或采用事务/修订检查；分批提交进度及可恢复任务；提供引用与文件一致性检查。此处为代码路径分析，未对真实图库做并发或故障注入。

## 4. 用户行为及系统异常清单

| 编号 | 触发情形 | 可能结果 | 目前恢复/预防边界 |
| --- | --- | --- | --- |
| S01 | 清空或删除 Chrome 下载记录 | 采集图消失；预览、描述、来源等连带被删 | R01；需优先改代码，不能只要求用户永远不清历史 |
| S02 | 浏览器下载记录长期超过默认查询量 | 图库漏图、数量变少、搜索不到 | R02；不等同物理文件丢失 |
| S03 | 移动/改名采集原图、ArchBuddy 目录或盘符；外置盘断开 | 原路径定位失败，现有预览可能仍可看 | 无通用重连；路径变化可恢复，删除文件则需原件备份 |
| S04 | 删除下载原图，或清理工具清空下载目录 | 原图真正丢失，仅剩低分辨率预览的可能性 | 保留预览不能恢复原图画质；外部原图备份 |
| S05 | 卸载后重装插件 | 扩展存储被移除，重装不是恢复 | 下载文件通常仍在；图库元数据和库内副本需完整备份 |
| S06 | 删除 Chrome 用户资料、重装系统时未保留资料，清理器直接删扩展数据库 | 大范围丢失索引、描述、Prompt与库内图片 | 完整备份保存在扩展外；仅同步浏览器账号不足以恢复本库 |
| S07 | 换 Chrome 用户资料、换浏览器/电脑、换到另一扩展ID的开发或商店安装 | 新库看起来为空，旧库可能仍在原资料中 | 回到原安装检查；跨安装通过受控备份恢复，不放松归属校验 |
| S08 | 停用扩展、更新/重载后保留旧标签页、旧书签指向另一扩展ID | 页面打不开或消息失效，不必然丢资产 | 重启用，通过当前插件入口重新打开；不要先卸载排障 |
| S09 | 误删单图、项目或整个提示词方案 | 预览/副本/描述/版本等被删除；勾选时还删除磁盘原图 | 当前有确认和默认不删原图，但无回收站/撤销 |
| S10 | 导入完成后删除电脑源文件，误以为已做双份备份 | 插件库可能成为唯一图片副本 | 普通源目录移动不影响已复制图片；卸载或数据库损坏后无源图可救 |
| S11 | 大批导入时关页、崩溃、断电、磁盘满 | 本批未完整登记、孤立 Blob、新保存失败 | 不意味着已完成的全库必丢；缺少任务级恢复与完整性报告 |
| S12 | 多个图库页与后台同时导入、描述编辑、移动、删除 | 元数据覆盖、整理结果回退、悬空引用 | R06；已有局部队列和导入锁，尚非统一协调 |
| S13 | 本地元数据配额达到上限、IndexedDB 配额/磁盘不足 | 新数据保存失败、原图与索引不同步 | R04；不能按固定图片张数预估整个库上限 |
| S14 | 浏览器存储压力回收、数据库损坏、硬盘故障 | 局部或整库丢失 | 回收是平台说明的少见风险；没有当前发生证据；需要持久化保护及外部备份 |
| S15 | 原网站失效、图片URL过期、防盗链、网络中断 | 未保存的预览无法补取、原网页无法回访 | 已成功保存的本地图片不应因此消失；下载和预览获取是两步，状态应分开 |
| S16 | 大图库一次读取/渲染、全尺寸导入图大量解码 | 卡顿、白屏、标签页崩溃，看起来无法访问 | 源码有全量列表及逐图加载；未压测，不能宣称特定数量会崩；需分页与专用缩略图 |
| S17 | 搜索词、分类、分组或失败筛选仍生效；语义索引不完整 | 以为图片丢失，实际只是不可见或搜索不命中 | 提供显示范围提示与清除筛选；关键词/全部图片兜底，索引可重建 |
| S18 | 未确认的编辑内容、描述尚未自动保存时立即关页/重启 | 最近编辑或会话草稿丢失 | 详情描述有700ms延迟及失焦保存；需明确保存中/已保存/失败；已入库与草稿分开 |
| S19 | 后续版本改变存储结构、迁移或降级处理有缺陷 | 旧图不可读、映射被错误重建或清理 | 属于未来升级风险，未发现当前安装初始化会清空整库；迁移前快照、可回滚、禁止读失败即重置 |

不应混淆的正常行为：

- 普通清缓存/浏览历史按 Chrome 官方说明不会直接清空扩展自己的 IndexedDB 与 storage.local；但若同时选择清下载记录，会触发本项目 R01 的间接删除。
- 关闭图库标签页、正常重启 Chrome，不应清空已持久保存的图库；正在进行的写入与会话草稿另论。
- 退出/切换 ArchBuddy 账号、AI 积分不足或后端不可用，不等于图库被清空。当前登录不提供云同步。
- 本地文件夹是复制导入，当前不存在需长期维持文件夹授权才能查看已导入图片的绑定模式。导入源路径仅是相对路径记录。
- 图库中的分类改名/项目跨分类移动是逻辑整理，不等于移动硬盘原图目录。

## 5. 建议产品优先级与验收方向

以下是评审建议，不是已获实施授权或已完成修复。对应需求池 AB-007“首次体验与本地资产可靠性”。

1. **先止住主动损失与漏图**：修复 R01/R02，让清下载记录只影响历史关联，不影响资产；下载历史不能再作为图库唯一目录。验收方向：清历史后数量、描述、来源、版本关联不变；超过1000条混合下载记录不漏图。
2. **建立用户可掌控的完整备份恢复**：备份资产包、恢复预检、完整性清单、上次备份时间；可选择原图目录补齐。验收方向：在空白浏览器资料中恢复，核对图片数量、字节校验、分类、描述、Prompt版本和关系；缺失原图必须明确列出。排除登录会话和凭据。
3. **误删除可撤销、失联可定位**：库内回收站；对历史丢失、文件缺失、权限/介质不可用、读取失败分别提示；用户选择新目录后按受控匹配重新关联。不能只按同名文件静默覆盖。
4. **保存与容量可信**：统一写入协调，分批提交导入任务，保存完成才显示成功，读失败不自动当空库覆盖；容量不足保留旧记录，给出可操作提示。物理磁盘容量与浏览器配额分开说明。
5. **确认支持的规模再对外承诺**：先用合成素材做1000/5000/10000张分档的人工验收，记录机器、图片大小、占用和耗时；不承诺无限图库。按章程不新增自动化测试框架；未来若要改变质量门槛另行确认。

建议将前两项作为鼓励用户长期大量积累素材之前的门槛。无需因此立即建设云同步或桌面客户端；本地网页形态可以保留，但必须配套独立目录、外部备份和恢复路径。
