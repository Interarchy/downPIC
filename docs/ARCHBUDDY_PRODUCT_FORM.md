# ArchBuddy 完整产品形态决策：插件 + 本地网页素材库

> **状态**：用户已确认的长期产品架构决定
> **确认日期**：2026-09-21
> **当前影响**：指导 V3 数据边界和后续版本规划，不把素材库开发提前塞入当前 V3 范围

## 1. 决策结论

ArchBuddy 的完整产品形态不是把所有能力继续堆叠在 Chrome 侧栏，而是由三个相互配合的产品层组成：

```text
Chrome 插件侧栏
负责网页场景中的轻量操作
        ↓ 打开素材库
插件内本地网页素材库
负责完整的资产管理和长时间工作
        ↓ 用户明确发起 AI 操作
ArchBuddy AI 服务
负责图片理解与结果评估，不默认保存用户图片
```

第一阶段的素材库采用随扩展打包的本地完整页面，例如：

```text
chrome-extension://<extension-id>/library.html
```

该页面在新的 Chrome 标签页中打开，视觉和交互上是完整网页，但与侧栏属于同一个扩展、同一个本地数据空间。当前不为素材库建立独立桌面客户端，也不默认把素材上传为云端资产。

## 2. 各产品层的职责

### 2.1 Chrome 插件侧栏：操作入口

侧栏服务于用户正在浏览网页或正在处理一张图片的即时任务，保留三个主流程：

1. **图片采集**：发现、下载和分类当前网页图片。
2. **提示词构建**：分析一张或多张参考图，选择并组合设计意图。
3. **效果优化**：导入外部生成图，对照当前 Prompt 定位偏差并形成下一版本。

侧栏强调“当前图片、当前方案、当前操作”，不承担大型网格浏览、复杂筛选和长期资产维护。

### 2.2 本地网页素材库：资产管理中心

素材库负责更适合宽屏页面完成的重操作：

- 参考图片网格与大图查看。
- 项目、分类、标签和搜索。
- 来源信息和用户确认的设计维度。
- Prompt 方案、来源参考图和版本历史。
- 从素材库选择图片继续进入提示词构建或效果优化。
- 后续增加导出、导入和本地备份。

素材库不是侧栏顶部的第四个工作流阶段。侧栏中应提供独立且明确的“素材库”入口，在新标签页打开完整页面；三个阶段仍表达用户的核心任务流程。

### 2.3 AI 服务：理解与评估引擎

AI 服务继续负责：

- 参考图的结构化视觉理解。
- 生成结果与当前 Prompt 的逐维度评估。
- 返回可解释、可选择的修改建议。

图片只在用户明确发起对应 AI 操作时发送。来源原图、生成结果和完整评估报告不因为建立素材库而自动成为云端资产。

## 3. 本地数据边界

第一阶段素材库与侧栏共享同一扩展 origin：

| 数据 | 建议存储 | 说明 |
| --- | --- | --- |
| 方案、标签、分类、Prompt 版本和图片元数据 | `chrome.storage.local` | 结构化、小体积、跨扩展页面共享 |
| 完整来源图片 | IndexedDB | 以 Blob 保存，方案和版本只引用图片 ID |
| 当前生成图和完整评估报告 | `chrome.storage.session` | 只用于当前会话，不长期资产化 |
| 模型密钥和服务端签名密钥 | 服务端环境变量 | 不得进入扩展、本地网页或仓库 |

侧栏和素材库页面必须复用同一套实体 ID、存储 Schema 和删除边界，不能各自建立互不相认的草稿与图片副本。

## 4. 为什么先做本地网页素材库

### 用户价值

- 素材管理需要宽屏网格、筛选和详情并列，侧栏不适合承载。
- 从插件直接打开，无需学习另一套产品或重复登录。
- 参考图、Prompt 和版本形成可持续复用的设计资产，而不是一次性分析结果。

### MVP 价值

- 复用 V3 已确定的本地方案、来源图和版本模型。
- 不需要先建设账户、云存储、跨设备同步和团队权限。
- 不影响已经上线的匿名 AI 调用与每日额度。
- 可以先验证用户是否真的会积累、整理并再次使用素材。

## 5. 已知限制

- 扩展卸载或浏览器配置被清除时，本地素材可能丢失。
- 浏览器本地存储不适合无限增长的大型图片库。
- 第一阶段不跨电脑同步，也不支持团队共享。
- IndexedDB 仍可能受浏览器存储压力影响，不能宣称为永久档案系统。

因此，在素材库面向真实长期使用前，必须提供清晰的本地边界说明，并优先评估导出/导入或备份能力。是否申请 `unlimitedStorage` 必须依据实际容量证据另行决定，不能提前增加权限。

## 6. Chrome Web Store 边界

- “采集、管理参考素材、构建 Prompt、评估生成结果”共同服务于一个清晰目的：帮助建筑设计师把视觉参考转化为可管理、可执行和可优化的设计意图，因此仍属于同一产品目的。
- 本地素材库页面及其 JavaScript 必须随扩展包发布；不得从服务器下载并在扩展权限环境中执行远程代码。
- 仅打开本地素材库页面不应申请无关或过宽权限。
- 即使图片只在本地保存，也必须在隐私说明和商店披露中如实说明处理方式。

## 7. 后续演进顺序

### 阶段 A：完成 V3 当前闭环

- 方案、来源图和 Prompt 版本使用可被侧栏与未来素材库共同读取的本地模型。
- 完成单图效果评估和复制形成下一版本。
- 不在 V3 里同时开发完整素材库页面，避免扩大当前范围。

### 阶段 B：本地网页素材库

- 新增 `library.html` 完整页面和侧栏“素材库”入口。
- 先实现浏览、搜索/筛选、查看来源、方案和版本、删除及明确的本地容量状态。
- 复用 V3 存储，不重复保存图片。

### 阶段 C：可选云端同步

只有真实用户验证了跨设备、备份或团队协作需求后再立项。云端同步必须：

- 由用户明确开启并说明上传内容。
- 使用独立 ArchBuddy 账户和访问控制。
- 所有集合、对象路径、缓存、日志和预算固定在 `archbuddy` 项目与明确阶段。
- 不混用 CloudBase 中 `st-` 或其他项目的数据与凭据。

### 阶段 D：桌面客户端（条件触发）

只有出现以下明确需求时才考虑：

- 管理大量本地文件夹和外部硬盘。
- 运行本地视觉模型。
- 与 CAD、BIM、渲染器或设计软件深度联动。

届时可评估 Chrome Native Messaging；桌面安装程序、系统注册、权限、更新和安全维护必须作为独立项目立项，不能作为素材库的默认前提。

## 8. 后续 Spec 的约束

- 后续素材库 Spec 必须把“侧栏即时任务”和“全页资产管理”作为两个界面层，而不是重复实现同一数据。
- V3 及其之前版本不得因为远期素材库而加入账户、云同步、团队协作或桌面程序任务。
- 任何涉及本地图片长期保留的功能必须定义容量失败、删除、卸载风险和备份路径。
- 任何云端素材能力必须单独经过隐私、成本和 CloudBase 多项目隔离评审。

## 9. 产品验证门槛

进入云端素材库或桌面端开发前，至少需要从本地素材库验证：

- 用户会持续加入并重新打开参考图，而不是只做一次分析。
- 用户能够通过项目、标签或搜索找到之前的素材。
- 来源图、结构化意图和 Prompt 版本之间的关联能帮助用户继续工作。
- 用户明确提出跨设备、备份、团队或大规模文件管理需求。

没有这些证据时，继续优化本地素材库，不提前建设重型平台。
