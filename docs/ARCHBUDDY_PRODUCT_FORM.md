# ArchBuddy 完整产品形态决策：插件 + 本地网页素材库

> **状态**：用户已确认的长期产品架构决定
> **确认日期**：2026-09-21
> **当前影响**：指导 V3 数据边界和后续版本规划，不把素材库开发提前塞入当前 V3 范围

## 1. 决策结论

ArchBuddy 的完整产品形态不是把所有能力继续堆叠在 Chrome 侧栏，而是由三个相互配合的产品层组成：

```text
Chrome 插件侧栏
负责网页场景中的轻量操作
        ↓ 打开素材库
插件内本地网页素材库
负责完整的资产管理和长时间工作
        ↓ 用户明确发起 AI 操作
ArchBuddy AI 服务
负责图片理解与结果评估，不默认保存用户图片
```

第一阶段的素材库采用随扩展打包的本地完整页面，例如：

```text
chrome-extension://<extension-id>/library.html
```

该页面在新的 Chrome 标签页中打开，视觉和交互上是完整网页，但与侧栏属于同一个扩展、同一个本地数据空间。当前不为素材库建立独立桌面客户端，也不默认把素材上传为云端资产。

## 2. 各产品层的职责

### 2.1 Chrome 插件侧栏：操作入口

侧栏服务于用户正在浏览网页或正在处理一张图片的即时任务，保留三个主流程：

1. **图词库**：以直接按钮打开完整图词库，并管理网页图片工具使用的项目类型；图片采集和保存仍在网页图片工具。
2. **提示词生成**：分析一张或多张参考图，选择并组合设计意图。
3. **提示词优化**：导入外部生成图，对照当前 Prompt 定位偏差并形成下一版本。

侧栏强调“当前图片、当前方案、当前操作”，不承担大型网格浏览、复杂筛选和长期资产维护。

### 2.2 本地网页素材库：资产管理中心

素材库负责更适合宽屏页面完成的重操作：

- 用户采集图片按项目类型、项目名称两级目录浏览；已确认方案的来源参考图仍可查看。
- 项目、分类、标签和搜索。
- 来源信息和用户确认的设计维度。
- Prompt 方案、来源参考图和版本历史。
- 从图库选择采集图片进入提示词构建；已确认方案在词库里回看版本与整理分组。
- 继续补足本地导出和备份。

侧栏“图词库”提供全页入口与项目类型管理，打开页面后侧栏自动关闭。全页左侧栏上方以两个小图标切换“采集的图片”和“生成的提示词库”：图片按下载目录的项目类型、项目名称两级组织，左侧项目文件夹只列名称并可滚动，右侧打开文件夹后显示图片预览；提示词库将来源图与对应 Prompt 摘要一同展示，并允许用户把图片卡组织成命名分组。侧栏仍保留三个主栏，网页图片工具继续承担采集与保存。

### 2.3 AI 服务：理解与评估引擎

AI 服务继续负责：

- 参考图的结构化视觉理解。
- 生成结果与当前 Prompt 的逐维度评估。
- 返回可解释、可选择的修改建议。

图片只在用户明确发起对应 AI 操作时发送。来源原图、生成结果和完整评估报告不因为建立素材库而自动成为云端资产。

## 3. 本地数据边界

第一阶段素材库与侧栏共享同一扩展 origin：

| 数据 | 建议存储 | 说明 |
| --- | --- | --- |
| 方案、标签、分类、Prompt 版本、下载索引和图片元数据 | `chrome.storage.local` | 结构化、小体积、跨扩展页面共享 |
| 完整来源图片与新下载的缩略预览 | IndexedDB | 方案来源图保存原 Blob；新采集图仅额外保存限宽预览，电脑下载文件仍是原图 |
| 待确认生成图和完整评估报告 | `chrome.storage.session` | 当前优化会话使用，确认前不进入长期词库 |
| 确认入库的效果图 | IndexedDB | 用户确认提示词时与 Prompt 版本关联；只在本机扩展内保存，不上传为云端资产 |
| 模型密钥和服务端签名密钥 | 服务端环境变量 | 不得进入扩展、本地网页或仓库 |

侧栏和全页必须复用同一套方案 ID、来源图引用及删除边界。采集下载另有下载 ID 和限宽预览，不能把预览误称为电脑目录里的完整原图，也不能复制一套独立的提示词方案。

## 4. 为什么先做本地网页素材库

### 用户价值

- 素材管理需要宽屏网格、筛选和详情并列，侧栏不适合承载。
- 从插件直接打开，无需学习另一套产品或重复登录。
- 参考图、Prompt 和版本形成可持续复用的设计资产，而不是一次性分析结果。

### MVP 价值

- 复用 V3 已确定的本地方案、来源图和版本模型。
- 不需要先建设账户、云存储、跨设备同步和团队权限。
- 不影响已经上线的匿名 AI 调用与每日额度。
- 可以先验证用户是否真的会积累、整理并再次使用素材。

## 5. 已知限制

- 扩展卸载或浏览器配置被清除时，本地素材可能丢失。
- 浏览器本地存储不适合无限增长的大型图片库。
- 第一阶段不跨电脑同步，也不支持团队共享。
- IndexedDB 仍可能受浏览器存储压力影响，不能宣称为永久档案系统。

因此，在素材库面向真实长期使用前，必须在隐私说明与帮助文档提供清晰的本地边界说明，并优先评估导出/导入或备份能力。是否申请 `unlimitedStorage` 必须依据实际容量证据另行决定，不能提前增加权限。

## 6. Chrome Web Store 边界

- “采集、管理参考素材、构建 Prompt、评估生成结果”共同服务于一个清晰目的：帮助建筑设计师把视觉参考转化为可管理、可执行和可优化的设计意图，因此仍属于同一产品目的。
- 本地素材库页面及其 JavaScript 必须随扩展包发布；不得从服务器下载并在扩展权限环境中执行远程代码。
- 仅打开本地素材库页面不应申请无关或过宽权限。
- 即使图片只在本地保存，也必须在隐私说明和商店披露中如实说明处理方式。

## 7. 后续演进顺序

### 阶段 A：完成 V3 当前闭环

- 方案、来源图和 Prompt 版本使用可被侧栏与未来素材库共同读取的本地模型。
- 完成单图效果评估和复制形成下一版本。
- 不在 V3 里同时开发完整素材库页面，避免扩大当前范围。

### 阶段 B：本地网页素材库

- 新增 library.html 完整页面；侧栏首栏“图词库”提供入口，打开全页后自动关闭侧栏。
- 全页区分采集图片与提示词库；采集图片沿既有下载路径按项目类型、项目名称两级展示，提示词库保留方案、来源图、版本、搜索及删除。
- 复用 V3 方案与来源图；新下载仅生成扩展内缩略预览，既有下载从浏览器下载记录列出并可在文件夹中定位。

### 阶段 C：可选云端同步

只有真实用户验证了跨设备、备份或团队协作需求后再立项。云端同步必须：

- 由用户明确开启并说明上传内容。
- 使用独立 ArchBuddy 账户和访问控制。
- 所有集合、对象路径、缓存、日志和预算固定在 `archbuddy` 项目与明确阶段。
- 不混用 CloudBase 中 `st-` 或其他项目的数据与凭据。

### 阶段 D：桌面客户端（条件触发）

只有出现以下明确需求时才考虑：

- 管理大量本地文件夹和外部硬盘。
- 运行本地视觉模型。
- 与 CAD、BIM、渲染器或设计软件深度联动。

届时可评估 Chrome Native Messaging；桌面安装程序、系统注册、权限、更新和安全维护必须作为独立项目立项，不能作为素材库的默认前提。

## 8. 后续 Spec 的约束

- 后续素材库 Spec 必须把“侧栏即时任务”和“全页资产管理”作为两个界面层，而不是重复实现同一数据。
- V3 及其之前版本不得因为远期素材库而加入账户、云同步、团队协作或桌面程序任务。
- 任何涉及本地图片长期保留的功能必须定义容量失败、删除、卸载风险和备份路径。
- 任何云端素材能力必须单独经过隐私、成本和 CloudBase 多项目隔离评审。

## 9. 产品验证门槛

进入云端素材库或桌面端开发前，至少需要从本地素材库验证：

- 用户会持续加入并重新打开参考图，而不是只做一次分析。
- 用户能够通过项目、标签或搜索找到之前的素材。
- 来源图、结构化意图和 Prompt 版本之间的关联能帮助用户继续工作。
- 用户明确提出跨设备、备份、团队或大规模文件管理需求。

没有这些证据时，继续优化本地素材库，不提前建设重型平台。

## 2026-09-27 图词检索与维护补充

V4 增加可检索的本地视觉描述：采集图片右侧详情可生成或手工编辑核心视觉特征，生成沿用既有 AI 服务及额度，仅上传当前图片预览。两类素材顶部使用自然句拆词与建筑同义词检索，不上传查询，不声称已具备向量语义搜索。确认方案及版本不再按五份淘汰；侧栏只展示最近五份。

分类支持改名与拖动排序；文件夹卡片采用小标题加缩略图。用户可选择仅移出图库，或确认后删除单图、整个项目中登记的下载原图；电脑空目录保留，不触及未列入图库的文件。downloads.open 用于用户主动在系统程序打开原图，不引入桌面客户端。首次图片处理同意与动作按钮共同构成发送边界，评估重复勾选框移除。依旧不新增云资源，不上传整库资产。


### 2026-09-28：图库语义检索与下载自动描述

本轮替代 9 月 27 日的本地字面模糊检索与手动生成描述方案。搜索由现有 AI 服务按含义判断候选文本；新下载图片在单独开启图库 AI 后自动生成短描述并本地保存。搜索只在回车或点击搜索时发送查询和候选文字，自动描述只发送单张预览，均复用既有鉴权及模型额度，不建立云端素材库。用户可关闭该处理；旧图不会自动批量上传。详见 [本轮修订](../specs/003-local-asset-library/revision-2026-09-28.md)。本轮只在本地接入，云端服务和公开隐私页面尚未更新。

### 2026-09-28：本地文件夹导入与双阶段检索

用户选中的文件夹本身是一级项目类型，其下的文件夹是二级项目名称。同名一级类型与现有图库合并展示；重复导入按相对路径、大小与修改时间跳过。扩展只读取用户选择的 PNG/JPEG/WebP（单张不超过 10 MB），完整副本保存在本机扩展 IndexedDB，索引在 chrome.storage.local；不会移动或删除电脑原文件。导入图片可在图库查看、编辑描述、主动生成完整提示词；批量导入不会自动调用模型，以免大量消耗用户和项目日额度。跨类型拖动项目只更新图库的虚拟分类，下载目录和导入源目录均不改变。删除导入项目只清理扩展副本。

图库与词库输入时本地即时关键词匹配，回车或点击搜索后在已有结果上补充模型语义匹配，合并去重。关键词阶段不发送查询；模型调用沿用独立同意及 20/200 日额度。缺少描述的导入图仅能通过文件名与项目元数据参与语义查找，需要用户补充描述才能提高视觉内容召回。未涉及 CloudBase 资源、权限或部署。

### 2026-09-28：一次导入多个本地文件夹

侧栏与全页图库均支持把多个一级文件夹从电脑文件管理器一起拖入导入区；每个拖入的文件夹分别作为项目类型，其下目录仍是项目名称。按钮仍可用目录选择器导入。批量操作沿用同名类型合并、路径/大小/修改时间去重、格式与容量限制、电脑源文件保留的既有规则；不触发批量 AI 处理，也不新增浏览器权限或云端资源。

### 2026-09-28：导入图的系统看图软件入口

Chrome 的 `downloads.open` 只能打开浏览器登记的下载项；本地文件夹输入只提供相对目录及浏览器内 File，无法直接把原始绝对路径交给系统程序。因此用户首次请求查看导入图时，扩展按导入时的一级类型/项目，把同一原始项目的图写入默认下载目录下独立的 `ArchBuddy-系统查看` 文件夹，并通过下载项 ID 打开所选图。之后复用这些已登记的副本；原始导入文件不移动。用户在右侧详情单击预览或在卡片双击均可触发。准备较久时，如浏览器不再接受首次点击的用户手势，页面提供明确的再次打开按钮。

系统软件的左右键行为取决于本机默认看图软件；同一原始导入项目的副本放在同一物理目录，虚拟跨类型合并后不承诺系统软件能一次跨原始目录浏览全部图库图片。删除导入图时尝试清理其系统查看副本，失败时提示手动清理；卸载扩展不会自动删除下载目录文件。该路径仅在用户主动系统查看时生成磁盘副本，不在导入时批量复制到下载目录。未增加云端资源或浏览器权限。

### 2026-09-28：图库大图内左右浏览

项目图片卡双击、右侧详情图单击改为打开图词库内大图。大图提供左右按钮和方向键，按当前项目图片顺序切换；在全图库搜索结果中打开时，按当前搜索结果切换。直接查看不会触发浏览器下载。大图里的“用系统看图软件打开”是明确的独立操作：导入图仅在点击此按钮后按前述规则准备系统查看副本，插件下载图打开已登记原图。系统看图软件是否支持目录内连续浏览仍由本机程序决定，不影响网页内的左右浏览。该修订覆盖上一节所述的双击或详情预览直接触发系统查看的入口；不增加云端资源或权限。

### 2026-09-28：恢复直接用系统看图软件打开

用户再次确认图库查看大图应直接调用电脑默认看图软件，不经过网页内大图和额外打开按钮。图片卡双击、详情图单击均调用系统查看。插件下载图打开既有下载项；导入图首次打开沿用同一原始项目的 `ArchBuddy-系统查看` 副本，后续复用。浏览器可能在首次准备耗时较长时限制自动打开，此时显示重试入口；这是 `downloads.open` 的用户手势限制，不是常规确认步骤。系统软件能否按左右键浏览及排序由用户本机默认程序决定。此决策覆盖上一节的图库页内左右浏览；词库图片的网页预览保持不变，不涉及云端资源。

### 2026-09-28：本地混合向量检索 B 方向

用户选择将图片描述和提示词的向量索引保存在插件本地，不建设 CloudBase 向量库。用户单独确认后，经 ArchBuddy 服务调用 TokenHub 文本 Embedding：首次为已有素材分批建索引，新增或文本变化时只重算对应项；提交搜索只生成一次查询向量。输入时本地关键词结果立即可见，提交后在 IndexedDB 中做向量相似度排序并合并去重。删除素材后清理对应本地向量；关闭图库 AI 停止新模型请求。缺少视觉描述的旧图只能根据名称和项目等文字匹配，不能宣称读懂图片。未接入重排模型，先以检索延迟与真实任务召回为验收依据。2026-09-28 已验证本机专属 Key 与真实匿名向量接口；本地配置使用当前 Windows 用户加密存储，费用、真实图库检索质量和云端部署仍待验证。


### 2026-09-29：确认后的效果图入库与图库预览

用户确认的优化版 Prompt 应同时保留其评估用效果图、所依据的前一版 Prompt 和来源参考图。待确认图片仍只在会话中；点击“确认提示词并入库”后，图片 Blob 写入插件 IndexedDB，版本元数据只记录图片 ID、前一版 ID 和评估 ID。构建流程提供的最多三张图都归入同一 Prompt 版本；词库按图片卡展示参考图和已确认效果图，并用对应版本的文本参与搜索。
