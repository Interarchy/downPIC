# ArchBuddy｜AI 产品经理面试一页纸

> 2026-09-29。**V3 已上线 Chrome Web Store 并由项目所有者验收；V4 图词库和本地混合检索只完成本地联调，尚未上线。**

## 定位与用户任务

**面向方案研究和效果表达阶段的建筑设计师，把散落的参考图变成可找回、可编辑、可复用的视觉意图。** 几位设计师提供了探索性反馈：逐张保存、命名会打断找灵感；Notion 或印象笔记里的图片后来只能凭旧关键词找，逐渐闲置；AI 出图前需要可试看的 Prompt 初稿，从零写很费劲。准确人数与耗时尚未记录。

## 产品闭环与取舍

**采集／导入 → 项目归档与视觉描述 → 找图 → 最多三图结构化生成 → 人工编辑确认 → 外部生图 → 按维度评估 → 保存新版本。** 价值假设是缩短找图和重写 Prompt 的时间，提高旧素材、旧方案的复用。

| 决策 | 原因与边界 |
| --- | --- |
| 侧栏＋完整图词库 | 侧栏完成当前网页任务；宽屏页管理图库、分组与 Prompt 历史。外部 AI 工具负责真正生图。 |
| AI 建议＋人工确认 | 模型提取视觉特征、提示偏差；设计师决定保留、组合和修改的内容，确认后才成为版本。 |
| 本地索引＋云端模型 | 图片与 Prompt 主要在扩展本地；经 ArchBuddy 服务调用视觉模型和 TokenHub 文本向量。输入时即时关键词匹配，回车后一次查询向量在本机检索并合并结果；失败保留关键词。CloudBase 没有向量库。 |

## 迭代与证据

**采集及单图反推 → 多图可编辑 Prompt → 效果评估和版本 → 图词库、批量描述、混合检索。** 迭代顺序回应了上述采集、找回、起稿问题，并补上生成结果的纠偏与版本保留。批量描述中断后，又补了进度、失败定位和恢复。2026-09-29 本地图库快照为 **153 张图，145 张有描述，8 张缺描述**；有 153 条图库向量，其中 129 张导入图已核对描述指纹。这些是覆盖数据，**不是检索效果或外部用户成效**。

## 待验证与商业假设

先完成 [V4 Eval](ARCHBUDDY_V4_EVAL_REPORT.md)：12 条预标目标图查询、20 张描述抽样、完整任务计时和模型成本记录；再让 5–8 名目标设计师独立做任务。候选核心指标是**每周成功复用旧图或旧 Prompt 的项目数**，目前没有线上统计。商业上可探索个人本地版、提供备份／跨设备同步的付费个人版，以及提供共享项目与权限的团队版；是否建设云端统一向量检索，要由真实团队需求和单位成本决定。**付费意愿、召回率、耗时和 Token 成本仍未知。**

面试主线：**从建筑师工作流发现断点，用连续闭环替代孤立的图片下载和反推工具；用本地索引控制早期范围，再用任务效果与成本数据决定下一轮产品化。**
