# 浏览器插件低保真原型实施计划

日期：2026-08-09  
依据：[浏览器插件低保真交互原型设计](../specs/2026-08-09-extension-prototype-design.md)  
预计工期：1～2 天  
交付物：可在本地浏览器运行的单页交互原型、自动化逻辑测试、可用性测试脚本

## 1. 实施原则

- 使用原生 HTML、CSS 和 JavaScript，不引入前端框架或构建工具。
- 使用浏览器页面模拟建筑案例网站、插件弹窗和网页图片悬浮工具条。
- 不申请浏览器插件权限，不下载文件，不连接真实桌面应用。
- 交互状态与界面渲染分离，核心规则使用纯 JavaScript 单元测试验证。
- 每完成一个任务即执行对应验证，不把所有检查留到最后。

## 3. 任务一：建立静态原型骨架和测试入口

创建：

- `prototype/index.html`
- `prototype/styles.css`
- `prototype/src/app.mjs`
- `prototype/tests/`

实施内容：

1. 建立无需编译即可运行的 ES Module 页面。
2. 在 `index.html` 中预留模拟浏览器栏、文章区、插件 Logo 和插件弹窗挂载点。
3. 在 `app.mjs` 中初始化应用，不实现具体业务。
4. 使用 Node 内置测试运行器，不安装第三方测试框架。

验证命令：

~~~powershell
node --test prototype/tests/*.test.mjs
python -m http.server 4173 --directory prototype
~~~

验收：

- 本地地址能够打开页面。
- 浏览器控制台无报错。
- 测试命令可以正常启动，即使首个测试仅验证基础环境。

## 4. 任务二：实现项目类型校验

创建：

- `prototype/src/project-type.mjs`
- `prototype/tests/project-type.test.mjs`

先写测试：

1. “文化建筑”校验成功。
2. 名称首尾空格被去除并返回“文化建筑”。
3. 空字符串校验失败。
4. 纯半角空格校验失败。
5. 纯全角空格校验失败。
6. 纯换行和制表符校验失败。
7. 内部合法空格保留，例如“城市 更新”。

再实现：

- 统一规范化项目类型名称。
- 返回明确的成功值或“请输入项目类型”错误。
- 插件弹窗和悬浮工具条必须调用同一校验函数。

验证命令：

~~~powershell
node --test prototype/tests/project-type.test.mjs
~~~

## 5. 任务三：实现共享状态模型

创建：

- `prototype/src/state.mjs`
- `prototype/tests/state.test.mjs`

状态字段：

- `desktopConnected: true`
- `captureEnabled: false`
- `defaultProjectType: "文化建筑"`
- `customProjectTypes: []`
- `images: Record<imageId, savedProjectTypes[]>`
- `activeImageId`
- `activeToolbarState`

先写测试：

1. 初始默认类型为“文化建筑”。
2. 在弹窗修改类型后，悬浮工具条读取新值。
3. 在悬浮工具条修改类型后，弹窗及后续图片读取新值。
4. 同一图片、同一项目类型不能重复保存。
5. 同一图片可以保存到不同项目类型。
6. 有效自定义类型同时进入个人词库并成为默认值。
7. 无效自定义类型不改变任何状态。

实现要求：

- 使用单一状态源，禁止弹窗和悬浮工具条各自保存一份默认类型。
- 状态变更通过语义明确的动作函数完成。
- 保存结果由图片 ID 与项目类型共同判断。

验证命令：

~~~powershell
node --test prototype/tests/state.test.mjs
~~~

## 6. 任务四：制作模拟建筑案例网页

修改：

- `prototype/index.html`
- `prototype/styles.css`
- `prototype/assets/architecture-board.png`

实施内容：

1. 建立一个建筑案例详情页，包含项目标题、地点、简短介绍和 6 张不同尺寸的建筑图片。
2. 使用一张本地 3×2 建筑素材板，通过 CSS 定位分别展示 6 个独立场景，保证测试时不依赖网络加载。
3. 增加站点 Logo、作者头像和小图标，标记为非内容图片。
4. 每张内容图片设置稳定的 `data-image-id`。
5. 页面支持至少 1280、1024 和 768 像素宽度，不模拟移动端插件。

验收：

- 内容图片与非内容图片在结构上可区分。
- 图片加载失败时仍有可识别的占位状态。
- 页面滚动过程中插件弹窗和图片定位正常。

## 7. 任务五：实现插件 Logo 与右上角弹窗

修改：

- `prototype/index.html`
- `prototype/styles.css`
- `prototype/src/render.mjs`
- `prototype/src/app.mjs`

实施内容：

1. 点击模拟浏览器右上角插件 Logo 打开或关闭弹窗。
2. 弹窗显示已连接状态、图片保存功能开关、预设类型下拉框、始终可见的自定义输入框、“设为默认”和“打开桌面应用”。
3. 下拉框包含“文化建筑”“教育建筑”等预设项，以及用户已经提交的“我的类型”。
4. 预设与自定义互斥：输入自定义内容时取消预设选择，选择预设或“我的类型”时清空输入框。
5. 纯空白输入时显示“请输入项目类型”，“设为默认”不可用。
6. 点击“设为默认”只更新后续默认类型，不保存图片。
7. 点击弹窗外部或再次点击 Logo 关闭弹窗。
8. “打开桌面应用”在原型中只显示说明性反馈，不执行外部启动。

手动验收：

- 图片保存功能开关状态持续保留。
- 弹窗关闭后再次打开，默认项目类型正确。
- 所有表单控件可使用键盘操作并具有可见焦点。

## 8. 任务六：实现悬浮意图控制器

创建：

- `prototype/src/hover-intent.mjs`
- `prototype/tests/hover-intent.test.mjs`

先写测试：

1. 进入图片不足 150 毫秒时不显示工具条。
2. 停留达到 150 毫秒时显示。
3. 离开图片不足 300 毫秒时不收起。
4. 从图片移动到工具条时不收起。
5. 离开图片和工具条达到 300 毫秒后收起。
6. 保存中或结果反馈未完成时不被隐藏。
7. 快速从一张图片移动到另一张时清理旧计时器。

实现要求：

- 计时器通过可替换的调度接口注入，方便单元测试。
- 每次只允许一个活动工具条。
- 图片保存功能关闭时立即清理活动状态和计时器。

验证命令：

~~~powershell
node --test prototype/tests/hover-intent.test.mjs
~~~

## 9. 任务七：实现图片悬浮工具条与保存反馈

修改：

- `prototype/styles.css`
- `prototype/src/render.mjs`
- `prototype/src/app.mjs`

实施内容：

1. 工具条锚定图片内部上方，距顶部约 8 像素并水平居中。
2. 工具条始终显示预设类型下拉框、自定义类型输入框和“Save”三个第一层级控件。
3. 预设与自定义互斥；宽图片单行排列，窄图片允许自定义输入换到第二行。
4. 点击“Save”后模拟短暂保存中状态，并锁定重复点击；成功后同时更新后续默认类型。
5. 成功后显示“已保存到文化建筑”或实际类型。
6. 再次悬浮同一图片和同一类型时显示“当前项目已保存”。
7. 切换到其他类型后恢复“保存”，允许跨项目保存。
8. 自定义类型点击“Save”时一次完成创建类型、保存图片和更新默认类型，并进入“我的类型”。
9. 保存反馈结束后仍保留该图片的当前项目已保存状态。

手动验收：

- 工具条不覆盖图片右上角原生关闭区域。
- 图片本身的点击行为不触发保存。
- 工具条不会因鼠标从图片移入工具条而闪退。
- 长项目类型名称不会使工具条超出图片边界；窄图使用紧凑或折行策略。

## 10. 任务八：完成核心任务脚本和可用性记录表

创建：

- `docs/usability/extension-prototype-test-script.md`
- `docs/usability/extension-prototype-observation-sheet.md`

测试脚本必须包含：

- 测试前说明，不向用户透露按钮位置。
- 核心任务原文。
- 计时起点与终点。
- 犹豫、错误保存、重复保存和求助次数的记录口径。
- 任务后理解检查：“你认为刚刚修改的项目类型会影响哪些图片？”
- 1～5 分易用性评分及开放反馈问题。

观察表每位用户一行，至少记录：

- 是否完成。
- 完成时长。
- 项目类型正确图片数。
- 明显犹豫次数。
- 错误或重复操作次数。
- 是否理解默认类型同步。
- 易用性评分。
- 关键原话。

## 11. 任务九：自动化测试与浏览器验收

执行全部逻辑测试：

~~~powershell
node --test prototype/tests/*.test.mjs
~~~

浏览器验收路径：

1. 打开原型并确认采集默认关闭。
2. 打开插件弹窗并开启图片保存功能。
3. 保存前两张图片到“文化建筑”。
4. 在第 3 张工具条中切换为“教育建筑”。
5. 保存第 3～5 张，确认类型同步。
6. 再次悬浮已保存图片，确认同项目去重。
7. 切换项目类型，确认允许跨项目保存。
8. 输入空字符串、半角空格、全角空格、换行和制表符，确认全部禁止保存。
9. 快速扫过多张图片，确认工具条不会频繁闪烁或残留。
10. 使用键盘完成弹窗内的开关、类型选择和自定义输入。

视觉验收尺寸：

- 1280 像素宽。
- 1024 像素宽。
- 768 像素宽。

验收结果必须记录实际通过项和遗留问题，不能只写“测试通过”。

## 13. 不在本次实施范围内

- Chrome Extension Manifest。
- content script 注入真实网站。
- 图片真实下载或最高分辨率解析。
- 文件夹创建、网页标题清洗和重复文件哈希。
- 与 Windows 桌面应用通信。
- AI 图片描述、关键词和自然语言检索。
- 登录、账号、云服务和数据同步。

这些内容在交互原型验证通过后，单独形成真实下载技术验证计划。
