# AI 建筑素材库｜MVP 端到端验收清单 v1.0

## 1. 验收目的

验证用户能否完成以下完整闭环：

> 浏览网页 → 选择项目类型 → 单张保存 → 自动归档 → AI 解析 → 人工修正 → 自然语言或筛选找回图片。

本清单同时用于区分“交互原型已表达”和“真实系统已实现”。只有真实文件、元数据、任务状态和搜索索引均通过集成验收，才能判定 MVP 闭环完成。

## 2. 验收层级

| 层级 | 验证对象 | 当前产物 |
| --- | --- | --- |
| L1 交互验收 | 页面、文案、状态、操作路径是否清楚 | 插件与桌面端原型 |
| L2 技术 POC | 图片下载、文件夹、离线暂存、AI 与索引是否可行 | 下一阶段实现 |
| L3 集成验收 | 插件、桌面端、本地文件和云端 AI 是否形成真实闭环 | MVP 集成版 |

状态填写规则：`未测 / 通过 / 有条件通过 / 不通过 / 阻塞`。

## 3. P0 发布门槛

以下条件全部满足，才允许将 MVP 标记为“可进入小规模用户测试”：

- 用户能在 30 秒内完成第一次单图保存。
- 每次点击 Save 只保存一张明确选中的图片，不扫描或批量下载整页。
- 图片进入正确的“项目类型 / 网页标题项目名”两级目录。
- 桌面端完全退出时仍可暂存，下一次启动后可自动导入。
- 新图片自动进入未解析队列，并最终生成非空描述和至少一个关键词。
- 人工修改描述或关键词后，搜索和筛选立即使用修改后的内容。
- 用户可通过自然语言、项目和关键词三种路径找回目标图片。
- 相同项目内重复文件不会生成重复副本。
- 保存失败、解析失败和离线状态均有明确原因与恢复入口。
- 来源网址、网页标题、网站名和保存时间可追溯。

任何一项 P0 门槛不通过，都不能以界面演示通过代替真实闭环通过。

## 4. 核心端到端场景

### E2E-01｜首次配置并完成在线保存

**层级：L1、L2、L3｜优先级：P0**

前置条件：首次安装插件和桌面端，桌面端在线运行。

步骤：

1. 启动桌面端并选择素材根目录。
2. 打开插件，开启图片保存功能。
3. 选择预设项目类型“文化建筑”。
4. 在案例网页上经过一张内容图片。
5. 点击图片上部居中的 Save。

预期结果：

- 未选择有效项目类型前不能开启或保存。
- 图片悬浮工具条不遮挡网页关闭控件，不改变图片原有点击行为。
- 每次点击只保存当前一张图片。
- 自动建立“文化建筑 / 网页标题项目名”目录。
- 图片文件真实存在，来源元数据完整。
- 插件显示保存成功，并提示图片已进入未解析。

证据：屏幕录像、文件夹截图、保存后的元数据记录。

### E2E-02｜自定义项目类型与输入校验

**层级：L1、L3｜优先级：P0**

步骤：

1. 在插件第一层级输入自定义项目类型。
2. 分别尝试空字符串、纯空格、重名和有效名称。
3. 使用有效名称保存一张图片。

预期结果：

- 空字符串、纯空格、换行、制表符和重名不能提交。
- 错误信息靠近输入框，Save 保持不可用。
- 有效名称成为第一层文件夹并被记为后续默认类型。

### E2E-03｜网页标题生成项目名称

**层级：L2、L3｜优先级：P0**

步骤：

1. 从有正常标题的网页保存两张图片。
2. 从标题为空、过长或含 Windows 非法字符的网页保存图片。

预期结果：

- 同一网页的图片复用同一二级项目文件夹。
- 标题会清理站点后缀、非法字符和首尾空白。
- 无有效标题时使用“网站名称＋采集日期”。
- 标题冲突时能够稳定消歧，不覆盖原项目。

### E2E-04｜重复图片处理

**层级：L2、L3｜优先级：P0**

步骤：

1. 在同一项目中重复保存同一张图片。
2. 切换项目类型后再次保存同一张图片。

预期结果：

- 同一项目内基于文件哈希去重，只保留一份。
- 插件显示“当前项目已保存”，不伪装成新保存成功。
- 不同项目允许独立副本，并轻提示其他项目已有副本。
- 已有 AI 解析结果可以复用。

### E2E-05｜桌面端完全退出后的离线暂存

**层级：L2、L3｜优先级：P0**

步骤：

1. 完全退出桌面端，而非仅关闭窗口。
2. 使用插件保存图片。
3. 再次启动桌面端。

预期结果：

- 插件明确显示“已暂存”，不显示为正式归档或已解析。
- 图片进入浏览器下载目录下的固定待导入目录。
- 项目类型、项目名称、来源和时间元数据没有丢失。
- 桌面端启动后自动导入正确目录，并进入未解析队列。
- 暂存失败时显示真实原因和重试入口。

### E2E-06｜自动 AI 解析与状态变化

**层级：L1、L2、L3｜优先级：P0**

步骤：

1. 保存一张新图片。
2. 观察未解析队列。
3. 等待 AI 任务结束。

预期结果：

- 状态依次为等待中、解析中、已解析，且数量同步更新。
- 已解析图片同时具有非空描述和至少一个关键词。
- AI 优先从预设词库选择，也允许生成自定义关键词。
- 关键词和描述完成后立即进入搜索索引。
- 临时失败自动重试最多 2 次；仍失败则显示原因和人工重试入口。

### E2E-07｜人工修正与撤销

**层级：L1、L3｜优先级：P0**

步骤：

1. 打开一张已解析图片的详情面板。
2. 修改图片描述。
3. 点击标签正文，确认不会删除；再通过右侧“×”连续删除三个 AI 关键词。
4. 连续执行两次撤销，再从全库已有关键词候选中复用一个关键词并新增一个自定义关键词。

预期结果：

- 修改自动保存并有清晰反馈。
- 库内候选排除当前图片已有关键词，支持搜索后点击添加；用户仍可创建新关键词。
- 撤销按钮显示剩余历史步数；同一图片最近 50 次编辑可连续回退，且不影响其他图片。
- 人工结果覆盖对应 AI 内容，不被普通重试恢复。
- 修改后的描述和关键词立即影响搜索和筛选。

### E2E-08｜自然语言找回目标图片

**层级：L1、L2、L3｜优先级：P0**

步骤：

1. 输入“有柔和天光的混凝土文化空间”。
2. 查看结果排序与匹配解释。
3. 清除自然语言条件。

预期结果：

- 输入时仅显示建议，不逐字请求 AI。
- Enter 或点击搜索后执行检索。
- 目标图片位于前列，并显示命中描述、关键词或语义的主要原因。
- 在线自然语言搜索 5 秒内返回。
- 清除查询后保留其他筛选条件。

### E2E-09｜自然语言重置旧筛选与结果后二次精筛

**层级：L1、L3｜优先级：P0**

步骤：

1. 选择项目类型“文化建筑”。
2. 选择关键词“清水混凝土”和“自然采光”。
3. 输入自然语言“带庭院的木结构学校”并提交。
4. 在自然语言结果出现后，再主动选择关键词“木构”。

预期结果：

- 提交自然语言后，之前的项目和关键词条件被清除，并提示正在检索整个素材库。
- 目标图片不会再被旧筛选条件排除。
- 结果出现后主动选择的“木构”与自然语言采用 AND，并以可清除条件显示。
- 本地关键词筛选 2 秒内返回。
- 空结果能够说明限制最强的条件，并提供恢复操作。

### E2E-10｜关键词个人分类拖动

**层级：L1、L3｜优先级：P0**

步骤：

1. 将“山地”从“形态”拖入“空间”。
2. 使用“山地”筛选图片。
3. 撤销移动。

预期结果：

- 目标分类在拖入时高亮并自动展开。
- 仅改变个人侧栏分类。
- 标签值、图片关联、搜索结果和系统原始语义维度不变。
- 撤销后回到原分类。

### E2E-11｜离线与服务降级

**层级：L2、L3｜优先级：P0**

步骤：

1. 在桌面端打开时断开网络。
2. 浏览已有图片并使用项目、关键词筛选。
3. 尝试自然语言搜索和 AI 解析。
4. 恢复网络。

预期结果：

- 本地图库、项目浏览、关键词筛选继续可用。
- 语义搜索和 AI 解析明确提示暂不可用，不丢失查询或任务。
- 网络恢复后任务可以继续或重试。

### E2E-12｜来源、版权与网站限制

**层级：L1、L2、L3｜优先级：P0**

步骤：

1. 保存来自普通图片、懒加载图片和受限网站的图片。
2. 在桌面端查看来源信息。

预期结果：

- 保存用户当前有权访问的最佳可用版本，不绕过网站访问限制。
- 无法访问或格式不支持时给出真实错误。
- 来源网址、网页标题、网站名和保存时间可查看。
- 产品不声称授予版权，版权提示不替代用户取得合法授权。

## 5. 首轮可用性任务

建议让测试者在不接受操作提示的情况下完成以下 5 个任务：

1. 保存一张“文化建筑”图片，并找到它在电脑中的真实文件夹。
2. 完全退出桌面端后再保存一张图片，重启后确认其自动导入。
3. 等待图片解析完成，并解释系统生成了什么。
4. 删除一个不准确的 AI 关键词，新增自己的关键词。
5. 仅凭一句设计意图重新找到第一张图片。

观察者只记录行为，不在任务进行中解释界面。

## 7. 问题分级

| 等级 | 定义 | 处理要求 |
| --- | --- | --- |
| S0 阻断 | 无法继续完成核心闭环，或存在数据丢失 | 必须修复后重测 |
| S1 严重 | 能绕行，但大多数用户会失败或误解 | MVP 发布前修复 |
| S2 一般 | 降低效率或信任，但不阻断任务 | 排入近期迭代 |
| S3 建议 | 偏好、文案或视觉优化 | 记录并结合频率判断 |

## 9. MVP 冻结规则

- 所有 P0 场景的 L1 交互验收必须通过。
- E2E-01、03、05、06、07、08 的 L2 技术 POC 必须通过。
- L3 集成版不得存在 S0 或 S1 问题。
- 若需求变化不影响核心闭环，进入下一版本，不继续扩大 MVP。
- 验收通过后冻结 PRD v1.0，并开始技术架构、数据模型和接口设计。
