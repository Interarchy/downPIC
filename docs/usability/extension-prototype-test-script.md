# 插件采集原型可用性测试脚本

## 1. 测试目标

验证建筑设计师能否发现并开启插件的图片保存功能，完成连续图片保存，并理解在图片工具条中切换项目类型会更新后续默认值。

## 2. 测试对象

- 3～5 名有网页找图和保存参考图片经验的建筑设计师。
- 不要求使用过本产品。

## 3. 测试准备

1. 在桌面浏览器打开原型首页。
2. 刷新页面，保证图片保存功能关闭且默认项目类型为“文化建筑”。
3. 准备计时器和观察记录表。
4. 不提前展示插件弹窗或悬浮工具条。

## 4. 主持人开场

请按平时浏览建筑案例的方式操作。这里没有标准答案，我们测试的是产品，不是你的能力。操作过程中请尽量说出你在看什么、准备做什么以及哪里让你犹豫。

## 5. 核心任务

计时从任务念完后开始：

> 请开启图片采集，保存 5 张你认为有参考价值的图片，并从第 3 张开始改存到“教育建筑”。

主持人不得提示插件图标、开关、工具条位置或项目类型切换方式。

计时在第 5 张图片显示保存成功后结束。

## 6. 观察口径

- 明显犹豫：停顿超过 3 秒，且没有继续滚动、阅读或操作。
- 错误保存：图片被保存到任务要求之外的项目类型。
- 重复操作：在没有改变项目类型时，再次尝试保存同一图片。
- 求助：测试者直接询问下一步应点击哪里或如何完成任务。
- 完成：5 张图片均保存，前 2 张为“文化建筑”，第 3～5 张为“教育建筑”。

## 7. 任务后提问

按顺序询问：

1. 你认为刚刚在第 3 张图片修改的项目类型，会影响哪些图片？
2. 如果想把同一张图片再保存到其他项目，你会怎么做？
3. 工具条的位置是否遮挡你观察图片？
4. 哪一步最不符合你的预期？
5. 如果满分为 5 分，你会给这段操作的易用性打几分？为什么？

## 8. 成功标准

- 60 秒内完成核心任务。
- 5 张图片项目类型全部正确。
- 最多出现 1 次明显犹豫。
- 无需主持人提示。
- 测试者能说明第 3 张修改类型后，第 3～5 张沿用新类型。

## 9. 主持原则

- 不纠正测试者，除非原型无法继续。
- 先记录行为，再询问原因。
- 不用“你为什么没看到”一类带有判断的问题。
- 出现原型故障时单独标记，不计为用户错误。
