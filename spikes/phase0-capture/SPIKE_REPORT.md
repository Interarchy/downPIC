### 4.1 重点站点首轮兼容修正

2026-08-11 基于真实页面复现并完成 `0.2.3` 修正：

- 小红书：首页内容图常为无扩展名 URL，例如路径包含 `!nc_n_webp_mw_1`；格式识别已支持 URL 路径与参数中的 WebP/JPEG/PNG 标识。
- Pinterest：首页图片上方存在点击覆盖层；悬浮识别已改为同时检查鼠标位置下的元素栈与近邻容器。
- ArchDaily：同时存在覆盖层与 1×1 懒加载占位图；尺寸判断加入实际布局尺寸，并从 `data-src`、`data-original`、`data-lazy-src` 获取真实地址。
- Chrome 下载栏：临时下载历史改为在宿主移动文件前清理，并在扩展更新或 Chrome 启动时清理既有“索引室待导入”历史项。
- 自动化回归 33/33 通过；真实站点最终交互需在 Chrome 重新加载扩展后复测。

### 4.2 异步状态与站点内图片传输修正

2026-08-11 根据第二轮实测升级至 `0.2.4`：

- 确认 Pinterest 已有图片成功归档，但快速下载时终态回执可能早于网页工具条记录 `captureId`，造成界面一直显示“正在下载”。
- 新增最近 50 条采集状态缓存；网页建立 `captureId` 后主动补取状态，修复快速完成时的回执竞态。
- 小红书与 Pinterest 优先在来源页面上下文读取图片 Blob，并以实际 MIME 类型进入 Chrome 暂存下载；页面读取失败时由扩展后台再次尝试，最后才回退原始直链。
- Pinterest 覆盖层命中多个图片元素时，按最近卡片容器内显示面积选择内容图，提升瀑布流小图悬浮识别。
- 扩展更新时会取消并清理超过 2 分钟的遗留下载任务，反馈可重试状态，避免永久“正在下载”。
- 本轮构建成功，相关自动化回归 33/33 通过。

### 4.3 小红书本地宿主获取链路

2026-08-11 第三轮实测确认页面 Blob 与后台直链仍不稳定，升级至 `0.2.5`：

- 小红书采集改为优先发送 `capture.fetch`，由 Native Host 使用来源页、正常浏览器标识和签名图片 URL 获取文件，再进入既有校验、去重、来源记录和两级目录归档流程。
- 生产环境仅允许 HTTPS 且域名属于 `xhscdn.com` 或 `xiaohongshu.com`，拒绝任意 URL，避免形成通用下载代理。
- Native Host 不可达时仍保留 Chrome 暂存回退；Host 已返回站点获取错误时不再进入已知会卡住的直链下载，而是在浮框显示真实失败原因。
- 增加本地 HTTP 测试服务器验证获取、归档与非允许域名拒绝；相关自动化回归 33/33 通过。
